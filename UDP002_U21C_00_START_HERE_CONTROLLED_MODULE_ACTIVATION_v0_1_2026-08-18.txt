1. WHY THIS NODE EXISTS

U21B proves only that a Module Pack is structurally eligible for a later
self-test. It deliberately does not import or execute Module code.

U21C adds the next and only authorized execution step:

  fresh U21B static scan
    -> select one exact Module identity
    -> recheck immutable identities
    -> run only the Manifest-declared self-test in a bounded subprocess
    -> compare exit code and expected token
    -> write identity-bound activation evidence

U21C does not run production analysis, does not execute an S0-S7 pipeline and
does not declare an algorithm mathematically valid.


2. ENGINEERING MEANING

U21B answers:

  "Does this package look structurally safe enough to test?"

U21C answers:

  "Did this exact package version pass its own declared self-test under the
   current Engine version and controlled execution policy?"

An accepted self-test is a software admission result. It is not evidence that
the algorithm is correct on vehicle data. Algorithm Cards, TUNING Runs,
EVALUATION Runs and Golden Runs remain later requirements.

4. U21C BOUNDARY

U21C MUST:

- call the accepted U21B Registry through its public CLI to create a fresh
  temporary static Registry Snapshot before every activation attempt;
- select exactly one Module by ModuleId and ModuleVersion;
- require its U21B RegistryStatus to be SELFTEST_REQUIRED;
- bind evidence to exact Engine and Module identities;
- execute only SelfTest.Arguments declared in the accepted Manifest;
- use an argument list and shell=False;
- use the current Python interpreter for a Python .py Entrypoint;
- impose timeout and output-size limits;
- capture bounded stdout and stderr evidence;
- write the final evidence JSON atomically;
- return stable one-line diagnostics.

U21C MUST NOT:

- import every Python file during discovery;
- execute a Module whose U21B status is not SELFTEST_REQUIRED;
- accept user-supplied extra Module arguments;
- execute the Entrypoint.Callable production function;
- run production analysis data;
- mutate Module files, Manifest files or Registry output;
- convert SELFTEST_ACCEPTED into a claim of algorithm validity;
- use shell=True, eval, exec, pickle or dynamic source evaluation;
- update the frozen three machine contracts.


5. CONTROLLED EXECUTION IS NOT A SECURITY SANDBOX

The child process is bounded by timeout, output limit, exact command
construction and identity checks. This reduces accidental failure propagation.

It is not an operating-system security sandbox. A Module accepted for U21C
must still be an authorized local Module Pack. U21C must not claim that it can
safely execute hostile or untrusted code. Container, Windows Sandbox and
network isolation are outside this MVP.


6. EXACT ACTIVATION IDENTITY

An accepted result is valid only for this tuple:

  EngineVersion
  ModuleId
  ModuleVersion
  ManifestSha256
  ImplementationSha256
  ConfigurationSchemaSha256
  RegistryProgramSha256
  ActivationPolicyVersion

If any value changes, previous evidence does not authorize the new identity.
The new identity returns to SELFTEST_REQUIRED and must be tested again.

Never treat ModuleId plus ModuleVersion alone as sufficient identity.


7. REQUIRED CLI

The controller has exactly two action modes.

7.1 Internal self-test

  --self-test
  --registry-program PATH
  --schema-bundle PATH
  --contract-validator PATH
  --fixture-manifest PATH

7.2 Activate one exact Module

  --activate-one
  --modules-root PATH
  --engine-version MAJOR.MINOR.PATCH
  --module-id MODULE_ID
  --module-version MAJOR.MINOR.PATCH
  --registry-program PATH
  --schema-bundle PATH
  --contract-validator PATH
  --out PATH
  --timeout-seconds INTEGER
  --max-output-bytes INTEGER

Exactly one action is required.

Defaults for --activate-one:

  timeout-seconds = 60
  max-output-bytes = 65536

Controlled limits:

  1 <= timeout-seconds <= 600
  4096 <= max-output-bytes <= 1048576

Controlled exits:

  0 = operation completed and the requested result is accepted
  7 = controlled denial, self-test failure or validation failure


8. FRESH STATIC PRECHECK

For --activate-one, U21C must:

1. Create a TemporaryDirectory owned by U21C.
2. Invoke the accepted Registry through sys.executable and its --scan CLI.
3. Pass modules root, engine version, Schema Bundle and Validator explicitly.
4. Require Registry exit code 0.
5. Parse the complete temporary Registry Snapshot.
6. Select exactly one entry matching ModuleId and ModuleVersion.
7. Reject zero matches or multiple matches.
8. Require RegistryStatus == SELFTEST_REQUIRED.
9. Require no PATH_ESCAPE, FORBIDDEN_SYMLINK, duplicate identity or hash reason.
10. Recompute Registry program SHA-256.
11. Resolve the selected Manifest from ManifestRelativePath.
12. Recompute Manifest, Entrypoint and Configuration Schema SHA-256.
13. Require all observed hashes to equal the fresh Registry Snapshot.
14. Load and validate the Manifest through the frozen Validator.
15. Require the validated Manifest identity to equal the selected Registry
    entry before any Module subprocess is created.

Any precheck failure must prevent Module execution.


9. PYTHON ENTRYPOINT POLICY FOR VERSION 0.1

ContractVersion 0.1 does not declare a general runtime type. Therefore U21C
v0.1 supports only an Entrypoint.RelativeFile whose final suffix is .py.

Command construction is exactly:

  [sys.executable, absolute_entrypoint, *Manifest.SelfTest.Arguments]

Use shell=False and cwd equal to the Module Pack root.

Any non-.py Entrypoint is denied with:

  UNSUPPORTED_ENTRYPOINT_RUNTIME

Do not guess whether another file should be executed directly. A future
runtime-type contract extension requires a separately versioned decision.


10. ENVIRONMENT POLICY

Build a reduced child environment from an allowlist of operating-system keys
needed for normal Python execution on Windows/macOS/Linux:

  SystemRoot, WINDIR, TEMP, TMP, TMPDIR, COMSPEC, PATH, PATHEXT, HOME

Environment-key comparison must be case-insensitive on Windows.

Force these values:

  PYTHONNOUSERSITE=1
  PYTHONDONTWRITEBYTECODE=1
  PYTHONUNBUFFERED=1
  U002_SELFTEST=1
  U002_MODULE_ID=<selected ModuleId>
  U002_MODULE_VERSION=<selected ModuleVersion>

Do not pass raw data paths, DBC contents or vehicle signal values through the
environment.


11. BOUNDED CHILD PROCESS

Use subprocess.Popen with shell=False, stdout=PIPE and stderr=PIPE.

Read stdout and stderr concurrently so one full pipe cannot deadlock the
process. Retain at most max-output-bytes in total. If the combined output
exceeds the limit:

- terminate/kill the direct child;
- mark OutputLimitExceeded = true;
- reject activation;
- retain only bounded output tails and byte counts.

If timeout expires:

- terminate/kill the direct child;
- mark TimedOut = true;
- reject activation.

Always wait for direct-child termination and close pipes. Do not leave a
successful activation result after timeout or output-limit termination.


12. SUCCESS DEFINITION

SELFTEST_ACCEPTED requires all of the following:

- fresh U21B Registry precheck passed;
- exact identity and hash checks passed immediately before execution;
- Python entrypoint policy passed;
- no timeout;
- no output-limit exceedance;
- observed exit code equals SelfTest.ExpectedExitCode;
- SelfTest.ExpectedToken occurs as one complete non-empty line in stdout;
- atomic evidence write succeeded.

Substring matching inside another line is prohibited. Normalize only line
endings for token comparison; do not otherwise rewrite stdout.

ReasonCodes and Warnings must be sorted stable uppercase strings.

Write failed-attempt evidence when --out is available and safe to use. A
failed-attempt evidence object must never have ActivationStatus
SELFTEST_ACCEPTED. Do not leave a partial JSON file.


14. NO MUTATION AND INVALIDATION RULE

U21C does not change RegistryStatus inside U21B output and does not mutate the
Module Manifest. Static Registry Snapshot and dynamic activation evidence are
separate evidence layers.

Effective availability in a later node is the join:

  fresh Registry entry with SELFTEST_REQUIRED
  + accepted U21C evidence
  + exact equality of every identity in Section 6
  = dynamically qualified Module identity

The later Engine resolver will perform this join. It is not part of U21C.


15. INTERNAL SELF-TEST

Use tempfile.TemporaryDirectory and the accepted valid_module_manifest.json as
the base fixture. Do not modify the accepted fixture.

Create synthetic Python Module Packs for at least:

1. correct exit and exact token -> SELFTEST_ACCEPTED;
2. correct exit but wrong/missing token -> denied;
3. wrong exit code -> denied;
4. timeout -> denied and direct child terminated;
5. output limit exceeded -> denied and output bounded;
6. U21B static denial -> Module marker proves it was not executed;
7. Manifest/implementation/config hash evidence is exact;
8. only Manifest-declared arguments reach the child;
9. child cwd is the Module Pack root;
10. evidence file is atomic, complete and parseable;
11. accepted evidence becomes unusable when a bound hash changes;
12. unsupported non-.py entrypoint is denied without execution.

The internal self-test must perform exactly 24 named assertions and print only:

  U21C1 N-T24-A1-F4-B2-H5-E1-X0 C-0

Meanings:

  T24 = 24 named assertions passed
  A1  = one positive Module self-test accepted
  F4  = token, exit, timeout and output-limit failures denied
  B2  = static-denied and unsupported-runtime Modules blocked before execution
  H5  = five required activation identity/hash bindings verified
  E1  = atomic parseable evidence output verified
  X0  = no uncontrolled exception

On internal self-test failure print only:

  U21C1-ERROR-<STABLE_REASON> C-7
