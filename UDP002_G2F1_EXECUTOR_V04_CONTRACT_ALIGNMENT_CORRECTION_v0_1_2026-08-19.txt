4. CANONICAL EXECUTIONORDER CONTRACT

The formal U21D Plan representation is now explicit:

  ExecutionOrder: list[str]

Each entry is exactly:

  ModuleId@ModuleVersion

Example shape only:

  ["U002.ModuleA@0.1.0", "U002.ModuleB@0.1.0"]

The separator is the final `@`. Both sides must be non-empty. ModuleId and
ModuleVersion retain their already validated Manifest identities.

Implement one dedicated pure function with equivalent semantics:

  parse_execution_order(plan: Mapping[str, object])
      -> list[tuple[str, str]]

Required algorithm:

1. Require plan["ExecutionOrder"] is a non-empty list.
2. Require every item is a string; bool, number, list and object are denied.
3. Require no leading/trailing whitespace and no empty string.
4. Split with `rsplit("@", 1)`.
5. Require exactly one usable final separator and non-empty ModuleId/version.
   An additional `@` remaining in ModuleId is denied for this contract.
6. Require `(ModuleId, ModuleVersion)` pairs are unique.
7. Require `SelectedModules` is a non-empty list of mappings.
8. Require every SelectedModules entry has:
     PlanOrder: integer but not bool;
     ModuleId: non-empty string;
     ModuleVersion: non-empty string.
9. Require PlanOrder is exactly zero-based contiguous:
     [0, 1, ..., n-1]
   with no duplicate, gap, negative value or bool.
10. Sort SelectedModules by PlanOrder and project exact identity tuples.
11. Require parsed ExecutionOrder tuples exactly equal that projection.
12. Return a new tuple list. Never mutate Plan or SelectedModules.

Any violation is a controlled exit-7 `K-PLAN_SEMANTICS` before Run creation.
Do not accept object-form order entries, ID-only strings, missing versions,
case-insensitive matches, whitespace normalization, duplicates, reordering or
automatic repair.
