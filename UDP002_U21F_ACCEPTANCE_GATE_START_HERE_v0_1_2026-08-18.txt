7.2 Protocol acceptance

7.3 Repeatability

Run the Executor self-test twice as separate child processes using the same six
input identities and two separate Gate-owned child evidence directories.

Both executions must:

- exit 0;
- end with exactly:

    U21F1 N-T36-R3-M12-A10-F10-I8-X0 C-0

- produce no uncontrolled traceback in stderr;
- retain bounded logs;
- leave every tested input hash unchanged.

Do not normalize or replace U/I keys or counter values.

7.4 Eight fail-closed denial probes

Run eight isolated negative CLI probes against the Executor:

1. no action;
2. --self-test with missing Engine path;
3. missing Protocol Bundle path;
4. missing Protocol Validator path;
5. missing Core Schema path;
6. missing Core Validator path;
7. modified private copy of the Protocol Bundle;
8. an input path that is a directory instead of a regular file.

Each probe must exit nonzero, emit a controlled C-7 result, create no accepted
Run/Artifact and never modify a tested source. A Python launch failure or raw
uncontrolled traceback is not an accepted denial.

Parse the exact Executor source with ast/tokenize and reject unless all hold:

1. source parses and declares the three documented actions;
2. candidate/Engine/validator modules are not imported as libraries;
3. no ThreadPoolExecutor, ProcessPoolExecutor or multiprocessing execution is
   present in the parent control plane;
4. no newest/mtime/ctime-based file selection is present;
5. subprocess execution and explicit path arguments are present.

These checks are boundary evidence, not a substitute for runtime results.
