版本：v1.0｜日期：2026-08-28

为什么需要这一步
--------------
H6B0 已确认：公司电脑中存在多个 Legacy 包，但不存在真实 High-Code H5 包。
因此现在不能直接运行差分比较。H6B1 会：

1. 从 H6B0 清单中筛出并排序可用 Legacy Reference；
2. 自动寻找 03_CASES 内包含 CANDump.csv 和 DBC 的真实源文件组；
3. 生成 provisional selection，供下一步 H2→H5 真实复跑使用；
4. 保持只读，不修改任何源文件或已有 D1–D6 包。

排序不是最终认定
--------------
Legacy 推荐顺序只用于缩小范围，依据依次为：
- 已通过 H6B0 正式路径与状态检查；
- 优先位于 03_CASES；
- 优先明确标记 release/final/accepted；
- 优先覆盖更多 FrameCount；
- 修改时间只作最后的并列判定。

H6B1 不会因为文件较新就直接批准它，也不会开始正式差分。

回传
----
只回传最后一行机器码，例如：
U1H6B1-L6-G2-R013-S1-P1-H0-A1-X0-C0

字段：
L = 可用 Legacy 包数量
G = Legacy 身份/范围组数量
R = 暂定推荐 Legacy Candidate 数字编号
S = 找到的 CAN 真实源文件组数量
P = 位于标准 03_CASES/.../00_SOURCE-READONLY 路径的首选源组数量
H = 已存在的真实 High-Code H5 包数量
A = 是否仍存在选择歧义（1=有，0=无）

后续判断
--------
- P1：源文件组唯一，可准备真实 H2→H5 复跑。
- G1：Legacy 身份范围唯一；仍需在 B2 计算 Hash 并确认与真实源身份相符。
- A1：不代表失败；下一步使用短编号消除歧义，不要求手动输入长路径。
- H0：符合当前已知状态；下一步目标就是生成 H1。
