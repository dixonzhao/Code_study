U003 EVIDENCE REVIEW WORKBENCH MVP v0.1
USER OPERATION MANUAL
Date: 2026-07-31

1. WHAT THIS PROGRAM DOES

U003 helps an engineer verify anomaly candidates by showing test video and a
synchronized CAN review table at the same FrameCount. It supports precise
navigation, Event review, lag-aware row highlighting, plot-data export and
screenshot/report preparation.

It does not decide root cause and does not determine whether Camera or Radar is
correct.

2. DELIVERY

Required file:
  U003_Evidence_Review_Workbench_v0_1.exe

Python, VS Code and OpenCV do not need to be installed on the receiving computer.
Place the EXE in a local writable folder. Do not launch it directly from a
read-only network location.

3. FIRST LAUNCH

Double-click the EXE. First launch may be slower while Windows security scans
and extracts the packaged runtime.

The program creates:
  U003_Workspace\
    01_INPUT_VIDEO\
    02_EVENT_QUEUE\
    03_REVIEW_DATA\
    04_OUTPUT\
    05_LOGS\

For a portable investigation, copy working input files into these folders before
opening them from the GUI.

4. STANDARD REVIEW WORKFLOW

Step 1 - Open video
  Select the local test video. Confirm video FPS and total frame count.

Step 2 - Set FrameCount mapping
  Enter the known video-frame anchor and corresponding CAN FrameCount.
  Use 1:1 when one video frame corresponds to one FrameCount.
  Use Rate-based only when the two rates are known and different.

Step 3 - Load Event Queue (optional)
  Load a CSV containing Event ID and start/end FrameCount. Select an Event to
  jump directly to its start; use Event Start/End and Loop for inspection.

Step 4 - Load Review Data (optional)
  Load a narrow CSV containing FrameCount and the columns needed for human
  comparison. U003 displays every supplied column and places FrameCount first.

Step 5 - Confirm synchronization
  Compare the visible video FrameCount with the yellow table row. Apply an
  explicit positive/negative lag only when the offset has an engineering basis.
  The information bar shows exact or nearest-row selection.

Step 6 - Record the result
  Select review code 1-5 and enter a short memo. Save the current Event review.

Step 7 - Export evidence
  - Save Screenshot for the displayed video frame.
  - Export Plot CSV using independent Before/After FrameCount ranges.
  - Export Reviews to create full CSV and compact TXT outputs.

5. REVIEW CODES

  1 - Correct / expected
  2 - Incorrect / mismatch
  3 - Real target or scene change
  4 - Unclear
  5 - Video unavailable

The code is an engineering review disposition, not a root-cause label.

6. OUTPUT LOCATIONS

The accepted v0.5 core normally saves:
  - screenshots beside the selected video;
  - plot CSV beside the selected Review Data CSV;
  - review CSV/TXT beside the selected Event Queue CSV.

Therefore, use working copies inside U003_Workspace when outputs must remain in
one shareable investigation folder.

7. IMPORTANT INTERPRETATION RULES

  - Yellow means exact/nearest selected CAN row, not ground truth.
  - Lag is user-defined; record the value used.
  - A large Camera-Radar difference is a discrepancy until engineering evidence
    establishes a sensor error.
  - If the exact FrameCount is absent, note the nearest-row delta.
  - Do not treat U003 as an automatic anomaly detector.

8. QUICK TROUBLESHOOTING

EXE does not start:
  Move it to a writable local folder and retry. Check
  U003_Workspace\05_LOGS\U003_STARTUP_ERROR.txt if created.

First launch takes a long time:
  Allow Windows endpoint protection to finish scanning the onefile package.

Video cannot open:
  Try a supported local AVI/MP4/MOV/MKV/WMV/MPG/MPEG file. Codec support depends
  on the bundled OpenCV backend.

FrameCount position is wrong:
  Recheck the video anchor, CAN anchor, mapping mode and rate. Do not compensate
  for an incorrect anchor by inventing a lag.

CAN table has no yellow exact row:
  Read the nearest-row delta. Confirm the Review Data contains the requested
  FrameCount range.

Output is not under U003_Workspace:
  The validated core writes beside selected inputs. Use input working copies
  inside the workspace.

9. SAFE CLOSING

Stop playback and close the Main window. Keep the EXE together with any desired
U003_Workspace evidence. The temporary PyInstaller runtime is managed by the
operating system; do not manually edit it while the program is running.
