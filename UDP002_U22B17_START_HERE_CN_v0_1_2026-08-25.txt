UDP002 U22B17 执行指南
======================

为什么做 B17
------------
B15 把目标当成一个点，只计算目标中心的方位角。人工复核发现：

- C0010：车辆仍在正前方，但 Radar 单独丢失约 10 Frame，是明确的非几何对照；
- C0014、C0016：目标距离很近，即使目标中心角较大，车体的一部分仍靠近传感器中心线，因此 Radar 仍可能继续识别。

B17 使用 U001 已经受控输出的 Camera Width，把目标从“一个点”改成“具有横向宽度的角度范围”。它比较：

1. 目标中心角；
2. 车体最近边缘角；
3. 车体是否覆盖传感器中心线。

本实验不会修改 U001、不会修改已经通过 Golden Run 的 S1，也不会批准新的 Radar 视野阈值。

CMD 执行——三行
---------------
python U-UDP002\04_TEMP\u002_u22b17_target_angular_footprint_assessment_v0_1.py.txt --prepare

python U-UDP002\04_TEMP\u002_u22b17_target_angular_footprint_assessment_v0_1.py.txt --self-test

程序会自动从 B14 质量记录找到原始 Golden Run，再从该 Run 的 resolved plan 找到准确的 U001 六文件包；不需要手动填写 CAN ID，也不重跑 Decode。

只需回传这一行。

Capsule 解释
------------
- N：B14 Frame 总数
- E：Width 与中心几何同时可用的 Frame 数
- I：其中 Radar 无效 Frame 数
- O：Radar 无效且车体横跨传感器中心线的 Frame 数
- AUC-C：目标中心角对 Radar 无效的排序关联，乘以 1000
- AUC-N：车体最近边缘角对 Radar 无效的排序关联，乘以 1000
- K：保持的 Candidate 数

AUC 只用于比较两种几何表述，不是准确率、阈值或因果证明。
