U001 H4A 独立验收——公司电脑执行指南
版本：v1.0（2026-08-28）

目标
----
读取已经通过验收的 H3 更新流，把同一个 FrameCount 内的多次信号更新聚合成一行 Frame View。

本阶段只处理“同帧聚合”：
- FrameCount 本身只作为帧键，不作为普通信号列重复装入；
- 数值信号采用该帧最后一次更新；
- Event Flag 采用该帧内 ANY_TRUE；
- 不做跨帧保持；
- 不补零；
- 不合成不存在的 FrameCount；
- 不修改 H3 输入。

放置位置
--------
把下面文件放到：
C-CODE\U-UDP001\04_TEMP

文件：
u001_h4a_direct_acceptance_v1_0.py.txt

输入位置
--------
C-CODE\U-UDP001\04_TEMP\U1H3D_OUTPUT\h3_output

输出位置
--------
C-CODE\U-UDP001\04_TEMP\U1H4D_OUTPUT\h4a_package

执行方法
--------
在 CMD 中进入 C-CODE 根目录，只执行以下三行：

python U-UDP001\04_TEMP\u001_h4a_direct_acceptance_v1_0.py.txt --prepare
python U-UDP001\04_TEMP\u001_h4a_direct_acceptance_v1_0.py.txt --self-test
python U-UDP001\04_TEMP\u001_h4a_direct_acceptance_v1_0.py.txt --execute

每一步的意义
------------
1. prepare
   清理本阶段自己的旧输出，并检查 H3 包、H4策略编译器和Frame View Builder是否存在。

2. self-test
   检查同帧归约规则及Frame View构建器的固定行为，防止补帧、跨帧保持、补零或源数据修改进入H4A。

3. execute
   生成策略模板、批准确定性的同帧规则、编译策略、构建真实H4A包并核对行数和质量字段。

通过标准
--------
最终只需回传以 H4A- 开头并以 -X0-C0 结尾的一行。

若失败
------
只回传以 H4AE- 开头并以 -X1-C7 结尾的一行，不要手工修改核心程序。
