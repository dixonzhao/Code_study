3. DIRECTORY OWNERSHIP CONTRACT
======================================================================

The controller owns creation of:

- sibling incomplete Run root;
- 00_REQUEST;
- copied request file;
- 04_RESPONSE;
- 04_RESPONSE/LOGS;
- response/abort manifests and capsules;
- final atomic rename after complete validation.

Each accepted child exclusively owns creation of its own --out directory:

- C1 G1 child owns 01_G1_CATALOG;
- C2 G10A2 build child owns 02_PROFILE_CONFIG;
- C4 G10B1 child owns 03_DISCOVERY_DATA.

Before launching the corresponding child, its --out path must be absent.
The controller must not mkdir, touch, seed or otherwise pre-create it.

After a child succeeds, the controller validates that the child-created output
directory and required artifacts now exist.

If a stage-owned output path exists before its child launch, stop before launch
with category STAGE_OUTPUT_COLLISION.  Preserve the incomplete root and write
the abort evidence.  Never empty or reuse the directory.

C3 and C5 are read-only validators and do not own output directories.

======================================================================
4. UNIVERSAL SUBPROCESS LOGGING
======================================================================

Use one shared subprocess runner for every C1-C5 child invocation.

For every stage, including exceptions and nonzero exits:

1. launch with sys.executable, argument list, shell=False and explicit cwd;
2. capture stdout and stderr independently as text;
3. immediately write and close:
   04_RESPONSE/LOGS/<StageId>.stdout.txt
   04_RESPONSE/LOGS/<StageId>.stderr.txt
4. only after both log-write attempts, evaluate exit code, required tokens and
   output artifacts;
5. retain the logs on every failure.

If process creation itself raises before a child process exists, write the
exception category into the stage stderr log without an absolute path, use
ChildExitCode=NA and continue through normal abort evidence handling.

Do not keep a special C1-only logging path.  C1-C5 must use the same runner.

======================================================================
5. FAILURE CLASSIFICATION AND CAPSULE
======================================================================

Classify in this order:

1. STAGE_OUTPUT_COLLISION: child --out already existed before launch;
2. CHILD_LAUNCH: process could not be created;
3. CHILD_EXIT: process returned nonzero;
4. CHILD_ARTIFACT: process exit 0 but required output missing/empty;
5. CHILD_TOKEN: process exit 0 and artifacts exist but completion evidence is
   missing or rejected;
6. CHILD_VALIDATION: read-only child validator returned nonzero or lacked its
   required validation token.

Do not collapse all categories to CHILD_EVIDENCE.

Every C-7 terminal capsule includes:

G10C1-ERROR:<stage>:<category> E<exit_or_NA>-F<bits>-SO<bytes>.<lines>-SE<bytes>.<lines>-AB<0_or_1> C-7

For C4, F bits are:

1. 03_DISCOVERY_DATA child output directory exists;
2. accepted G10B1 root return capsule exists and is nonempty;
3. accepted G10B1 run manifest exists and is nonempty;
4. at least one update shard exists;
5. at least one frame shard exists.

The accepted child source must determine the exact return-capsule and manifest
basenames.  Do not invent or rename child outputs.  Resolve only exact expected
basenames; do not use timestamp or latest-file selection.

ABORTED_RUN includes StageId, Category, ChildBasename, ChildExitCode, artifact
bits, stdout/stderr statistics, and the last three sanitized nonempty lines of
stdout/stderr/child capsule.  Each tail line is at most 180 characters.  It
contains no absolute path or company data values.
