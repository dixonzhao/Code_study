UDP002 U22B13D — TC001 全视频 S0/S1/S6/S7 Golden Run 执行指南
版本：v0.1
日期：2026-08-25

一、目标

在已经通过验收的 U-UDP002 工作区内，使用以下固定链条处理 TC001 全视频：

S0 U001 Intake
→ S1 Camera Target Reconstruction 0.3.0
→ S1 Radar Measurement Validity 0.1.1
→ S6 Radar Measurement-Loss Candidate Synthesis 0.1.2
→ S7 U003 Review Batch Export 0.1.1

正式范围固定为 FrameCount 7400–57597。
本节点不会把 Candidate 称为 Radar error，也不会输出 root-cause 结论。

二、准备

1. 下载 UDP002_U22B13D_COMPANY_PACKET_v0_1_2026-08-25.zip。
2. 把 ZIP 内全部 16 个文件直接解压到：
   C-CODE\U-UDP002\04_TEMP
3. 不要改名，不要放入 04_TEMP 的子文件夹。
4. 以下三条命令均从 C-CODE 目录使用 CMD 执行。

三、只执行以下三条 CMD 命令

python U-UDP002\04_TEMP\u002_u22b13d_prepare_v0_1.py.txt --workspace-root U-UDP002

python U-UDP002\04_TEMP\u002_u22b13d_tc001_full_video_run_v0_1.py.txt --self-test

python U-UDP002\04_TEMP\u002_u22b13d_tc001_full_video_run_v0_1.py.txt --execute --workspace-root U-UDP002

四、PREPARE 的作用

- 校验 16 个当前文件的名称与 SHA-256；
- 把 04_TEMP 中旧文件和旧文件夹移动到 U-UDP002\A-Archive；
- 安装 U22 Core 兼容的 S6 0.1.2 与 S7 0.1.1；
- 保留历史证据，不直接删除旧文件；
- PREPARE 完成后，04_TEMP 只保留本次 16 个活动文件。

预期第一条结果以以下形式结束：

B13DP ... X0 C-0

五、自测与正式运行

第二条预期：

UDP002-U22B13D-SELFTEST-PASS-41 C-0

第三条会自动：

- 发现并核对已验收的 B1B4 全视频源 Run；
- 发现并核对 B11 Camera geometry 配置；
- 刷新 Registry 并资格化精确 Module 版本；
- 生成不可变 Run Configuration；
- 执行五个 Module；
- 审计全部 Artifact；
- 检查 Candidate 完整性、日英 ReviewTrace、批次分配和无截断条件。

六、成功结果与输出位置

成功时只需回传最后一行：

B13D N-F...-V...-R...-C...-B...-Q...-D...-J...-Z0-X0 C-0

字段：

F = 全视频 Frame 行数，预期 50198
V = Canonical Camera 有效行数
R = Radar 无效行数
C = 完整 Candidate 数
B = Review batch 数
Q = 已分配 Candidate 数，必须等于 C
D = Review data 总行数
J = 含完整日语 ReviewTrace 的 Candidate 数，必须等于 C
Z = 截断数，必须为 0

正式输出目录：

C-CODE\U-UDP002\07_OUTPUT\U22B13D_TC001_FULL_VIDEO_REVIEW_V01

回传文件：

C-CODE\U-UDP002\07_OUTPUT\U22B13D_TC001_FULL_VIDEO_REVIEW_V01\B13D_return_capsule.txt

七、失败时

不要让 Copilot 修改程序或 Core。请回传最后两行：

B13DE K-... P-... X1 C-7
B13DD D-... X0 C-0

如果已经出现 Run 目录，同时保留其中的 run_status.json、01_LOGS 和
02_DIAGNOSTICS，后续由项目侧统一判断根因。
