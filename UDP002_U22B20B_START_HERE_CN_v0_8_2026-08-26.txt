UDP002 U22B20B Thin GUI执行指南（中文）
版本：v0.8（Profile视觉优先级、Stage分组与输出去向校正版）
日期：2026-08-26

一、本节点做什么

B20A已经安装GUI Run Profile和Workbench Link契约。B20B在这些契约上安装第一版U002 Thin GUI。

Thin GUI只负责：

1. 选择U001 Accepted Package与运行范围；
2. 默认载入已经验收的Golden Module链；
3. 在Custom模式下查看、添加、删除、排序和配置已通过Registry验证的Module；
4. 生成不可变的正式Run Configuration；
5. 依次调用现有Validator、Preflight和Executor；
6. 运行成功后提供U003启动入口。
7. 启动时选择JA/EN；界面语言同时决定本次Run的Review Memo输出语言。
8. 让Stage边界、Module身份与Version选择、U001/U003连接动作在界面中可直接理解。

Thin GUI不会重新实现算法。现有CLI Golden Path保持不变。

“用户没有加载Module”的实际含义是自动使用Default Qualified Profile，不是生成空ModulePlan。

二、下载与解压

从Code_study下载：

1. UDP002_U22B20B_PACKAGE_v0_8.zip
2. UDP002_U22B20B_START_HERE_CN_v0_8_2026-08-26.txt

把ZIP内三个文件解压到：

C-CODE\U-UDP002\04_TEMP

同时把本START_HERE放入同一目录。

最终应有：

- u002_u22b20b_thin_gui_installer_v0_8.py.txt
- u002_thin_workbench_model_v0_4.py.txt
- u002_thin_workbench_gui_v0_6.py.txt
- UDP002_U22B20B_START_HERE_CN_v0_8_2026-08-26.txt

不要改名，不要再创建B20B子文件夹。

三、CMD执行

当前目录必须为C-CODE，只执行以下三行：

python U-UDP002\04_TEMP\u002_u22b20b_thin_gui_installer_v0_8.py.txt --prepare --workspace-root U-UDP002
python U-UDP002\04_TEMP\u002_u22b20b_thin_gui_installer_v0_8.py.txt --self-test --workspace-root U-UDP002
python U-UDP002\04_TEMP\u002_u22b20b_thin_gui_installer_v0_8.py.txt --open-gui --workspace-root U-UDP002

Prepare和Self-test会用英文显示：检查了什么，以及为什么检查。两步C0时不用回传。

Prepare会先调用正式Module Registry刷新Snapshot。若Profile、Module版本、Registry、Core路径或其他依赖失败，最后一行会直接保留具体原因。

v0.3不再把本地测试用的FULL_CASE当成固定产品规则。GUI会保留B20A Golden Profile的真实RunScope；FULL_CASE要求起止Frame为空，FRAME_RANGE/FILTERED_RANGE则要求显式合法的FrameStart和FrameEnd。

v0.4同时把U003路径明确作为可选的本机便利设置。以前保存过但现在失效的U003路径不会阻止U002 Self-test或分析；真正点击Open U003时才检查该文件是否存在。

v0.8继续只修正GUI信息层级与运行后去向，不修改分析逻辑、Data Contract、Module算法或Golden配置。

Profile窗口不再要求理解Clone as Custom。界面提供Load Sample Profile、Save Profile、Open Profile；用户第一次修改Module、Configuration、PrimaryOutcome、SignalProfile或CandidatePolicy时，程序自动进入Editable Working Profile。若用户完全不修改Sample，仍保持Default Qualified语义，供B20C和CLI Golden配置比较。

保存的Profile只包含可复用分析选择：SignalProfile、ModulePlan、PrimaryOutcome、CandidatePolicy、OutputSelection。它不保存RunId、U001 InputPackage、RunScope或Frame范围，打开Profile时这些当前Case字段保持不变。

Add Qualified Module改成左右两区：左侧是可换行的Module卡片，右侧是较大的Available Versions真实版本列表。Registry本身已经只返回合格可用项，因此不再重复显示整列AVAILABLE。

v0.8进一步按S0-S7插入明显的Stage分组标题；右侧Version区大于左侧Module区。选择具体Version后，黑体Module标题下方显示来自该Version Algorithm Card的两行Purpose简介。

Profile区以Open Profile为最大主操作，Save Profile为次操作；Load Sample Profile缩小并放在右下角。Sample只用于恢复示例配置，不再抢占正常Profile工作的视觉中心。

Outcome and Output Settings增加运行后去向：默认进入U003 Evidence Review，或者启动一个完全独立的新U002。后者目前不传递数据；真正的U002派生数据回灌仍需SourceKind、ParentRunId、ArtifactRole和EntryStage契约，因此没有被伪装成已完成功能。

“新开U002”不会自动继承上一轮结果。本版仍只接受U001 Accepted Package作为根输入，避免把U002派生结果伪装成U001源数据。后续若需要循环分析，将另行增加带ParentRunId和ArtifactRole的派生输入契约。

启动GUI时必须先选English或日本語。该选择同时写入支持RequestedReviewLanguage的Module配置。点击“保存”“检查”或“运行”后，本次Run的语言立即锁定，右上角语言切换按钮禁用；若需要换语言，必须新建Run，不能让一个Run产生混合语言Review证据。

四、界面首次确认

GUI打开后先不要启动完整分析，只检查：

1. 启动时先出现English/日本語选择窗口；
2. 选择English后标题为U002 Analysis Workbench v0.6，选择日本語后显示日语标题；
3. Profile显示Default Qualified Profile；若语言选择改变了Golden Profile内的Review语言，则应如实显示Custom Profile；
4. Module表显示5个Module；
5. 顶部Stage条中S0、S1、S6、S7为激活状态；
6. Run Scope与B20A Golden Profile一致；如果是FRAME_RANGE/FILTERED_RANGE，能够看到对应的起止Frame；
7. 右上角分别显示U001 INPUT和U003 REVIEWER状态，不再出现笼统的Local Links；
8. 点击任一S0-S7方块会打开该Stage的小窗口；空Stage也可以打开；
9. 在Stage窗口中直接执行Add/Remove/Move/Edit；第一次修改时自动进入Editable Working Profile；
10. Edit Configuration默认是字段、下拉框和列表，不直接显示JSON；Raw JSON只作为Advanced入口；
11. Outcome/Output同样使用表单和列表；Execution Log继续保留文本形式，因为它本身就是诊断证据；
12. 选择一个Module并打开Algorithm Card，默认显示Overview/Mathematics/Interface/Validation/Limits，Raw JSON只在最后一个Tab；
13. 顶部另有VALIDATE/PREFLIGHT/EXECUTE状态块；本节点不启动正式分析，因此不要求S0-S7实际跑完变绿；
14. 正式流程成功后，如果U003已连接且勾选提示选项，GUI询问是否立即打开U003。
15. Edit Configuration中把鼠标放在字段区，滚轮可以上下移动；
16. 点击U001/U003彩色状态块即可选择对应路径，Reset可清空；
17. Module Plan中每个已占用Stage前有粗蓝色分隔行，选择分隔行不能执行Module编辑；
18. Add Qualified中左侧每个Module只出现一张可换行卡片；右侧Available Versions区域明显更大并逐条显示真实版本号；
19. “Ask to start a new U002”默认不勾选；勾选后只在成功运行结束时询问是否打开独立新窗口。
20. Profile区域显示Load Sample Profile、Save Profile、Open Profile，不再显示Clone as Custom；
21. 直接点击Add/Edit/Remove/Move即可修改，不需要先切换内部模式；
22. Save Profile保存后，Open Profile可以重新载入分析配置，同时当前RunId、U001输入和Frame范围不变。
23. Open Profile是Profile区最大按钮；Load Sample Profile只位于右下角且尺寸较小；
24. Add Qualified列表按S0-S7明确分组，右侧Available Versions区域宽于左侧；
25. 选择Version后，黑体Module标题下面显示两行以内的功能简介；
26. Outcome and Output Settings可选择U003 Review（默认）或独立新U002；界面明确说明新U002不接收上一轮数据。

本节点只验收GUI控制边界，不运行50,198帧全量分析。
