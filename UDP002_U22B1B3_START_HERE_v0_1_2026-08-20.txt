UDP002 U22B1B3 执行说明（Windows CMD）
版本：v0.1
日期：2026-08-20

一、本节点做什么

本节点在真实U001 Accepted Package上执行两个已经验收的Module：

S0：U001 Controlled Profile Intake
S1：Camera Target Continuity Arbitration

运行范围为：

FrameCount 7400
至 min(57597, U001实际FrameCount上限)

程序会生成完整Camera重建Artifact、一个仅含4列的Plot View，以及6个已知窗口组成的U003兼容复核队列。

本节点的C-0只表示技术验收通过。是否真正选中视频中的同一目标，仍需人工语义复核。

二、执行前提

必须已经完成：

U22B1AR ... C-0
U22B1B2 N-I1-Q1-P1-C1-F1-X0 C-0

不要删除此前正式生成的：

.\U-UDP002\07_OUTPUT 下的B1AR Run
.\U-UDP002\02_CONFIG\binding_profiles
.\U-UDP002\02_CONFIG\module_configs
.\U-UDP002\01_PROGRAMS\modules\S0
.\U-UDP002\01_PROGRAMS\modules\S1

三、下载文件

从GitHub下载以下3个文件，全部直接放进：

.\U-UDP002\04_TEMP

不要改名，不要放入A-Archive，不要让Copilot重写程序。

四、从C-CODE根目录执行

Step 1：Runner self-test

python .\U-UDP002\04_TEMP\u002_u22b1b3_real_s1_reconstruction_run_v0_1.py.txt --self-test

成功输出：

U22B1B3R-ST N-T19-X0 C-0

Step 2：Acceptance self-test

python .\U-UDP002\04_TEMP\udp002_u22b1b3_real_s1_reconstruction_acceptance_v0_1.py.txt --self-test

成功输出：

U22B1B3-ST N-T17-X0 C-0

Step 3：正式运行与技术验收

python .\U-UDP002\04_TEMP\udp002_u22b1b3_real_s1_reconstruction_acceptance_v0_1.py.txt --accept --workspace-root .\U-UDP002

成功输出形式：

U22B1B3 N-F<行数>-V<有效行数>-S<确认切换数>-Q<复核窗口数>-P1-X0 C-0

其中：

F = S1输出Frame行数
V = Canonical Camera有效行数
S = 经过hysteresis确认的Camera Source切换数
Q = 生成的语义复核窗口数；TC001完整范围应为6
P1 = 技术验收通过，但人工语义复核仍待完成
X0 / C-0 = 无技术错误

两个self-test通过时不需要回传。只回传Step 3最后一行。

如果出现C-7，立即停止，只回传该错误行；不要修改Runner、Gate或正式U22 Foundation。

五、主要输出位置

Run目录：

.\U-UDP002\07_OUTPUT\U22B1B3_<16位Hash>

完整受控S1 Artifact：

03_ARTIFACTS\S1\...\camera_target_reconstruction.csv
03_ARTIFACTS\S1\...\camera_target_reconstruction_quality.json

人工画图用4列表：

05_EXPORTS\u22b1b3_camera_reconstruction_plot_view.csv

列固定为：

FrameCount
Camera1Distance
Camera3Distance
CanonicalCameraDistance

U003兼容复核队列：

04_REVIEW_PACKAGE\u22b1b3_s1_semantic_review_queue.csv

技术验收记录：

u22b1b3_technical_acceptance_receipt_v0_1.json

六、工程意义

本节点第一次在真实数据上验证：

U001可信源表
→ S0 Intake Artifact
→ S1 Camera重建Artifact
→ 四列人工Plot View
→ U003语义复核队列

程序不会把技术C-0包装成Target Truth。下一节点必须使用U003确认6个窗口，才能决定当前Camera重建Algorithm是Keep、Modify还是Reject。

七、重放规则

相同U001输入、相同Binding Profile和相同S1配置会得到同一个RunId。再次执行时程序只允许读取并复核已经成功的Run，不会覆盖或重复制造Artifact。
