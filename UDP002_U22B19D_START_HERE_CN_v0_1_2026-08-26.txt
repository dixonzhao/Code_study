一、这一步在做什么

B19C 已经证明新的完整 Golden Run 正常结束，但新旧 Run 的 RunId、ArtifactId 和血缘记录必然不同。

B19D 不重新运行分析，也不要求你重复查看 16 个视频候选。它比较：

- S6：候选清单、逐帧证据、质量记录与 Module Review Trace；
- S7：完整候选清单、Event Queue、Review Data、Batch Index 与质量记录。

每个文件先按自身 artifact_manifest.json 校验 SHA-256、ByteSize 和 RowCount。随后：

- CSV 按表头和逻辑行逐字段比较；
- JSON/JSONL 仅移除 RunId、ArtifactId、ParentArtifactIds、SourceArtifactIds 等执行血缘字段后比较；
- 其他文件要求 SHA-256 完全相同。

因此，本步骤回答的是：U003真正看到的候选与证据是否改变，而不是两个运行目录的名字是否相同。

将以下两个文件直接放入：

C-CODE\U-UDP002\04_TEMP

1. u002_u22b19d_downstream_equivalence_v0_1.py.txt
2. UDP002_U22B19D_START_HERE_CN_v0_1_2026-08-26.txt

不要改名，不要创建子文件夹。

三、CMD执行（当前目录必须是 C-CODE）

python U-UDP002\04_TEMP\u002_u22b19d_downstream_equivalence_v0_1.py.txt --prepare --workspace-root U-UDP002
python U-UDP002\04_TEMP\u002_u22b19d_downstream_equivalence_v0_1.py.txt --self-test --workspace-root U-UDP002
python U-UDP002\04_TEMP\u002_u22b19d_downstream_equivalence_v0_1.py.txt --execute --workspace-root U-UDP002

prepare 和 self-test 会逐行显示“检查内容”和“WHY：为什么检查”。这是学习信息，不需要手工回传。

self-test 如果最后一行是 C0，不需要回传。

四、只回传 execute 最后一行

成功且可继承旧人工复核的典型格式：

B19D-S2-P...-E...-N...-M0-C16-B1-D1-H0-X0-C0

字段：

- S：比较的Stage数量，固定为2（S6和S7）；
- P：比较的Payload总数；
- E：字节级完全相同的Payload数；
- N：只有允许的Run/Artifact血缘字段不同、业务内容相同的Payload数；
- M：业务内容不同或缺失的Payload数；
- C：完整候选数量；
- B：Review Batch数量；
- D：下游业务结果是否等价；
- H：是否需要重新人工视频复核；
- X：技术阻塞数；
- C0/C7：节点状态。

判定：

- D1-H0：原有16个候选的U003人工复核结论可以继承，不再重复看视频；
- D0-H1：程序正常完成比较，但存在业务差异。下一步只复核新S7 Package，不重复运行Golden Run；
- C7：技术问题，只回传完整失败行，不自行修改程序。
