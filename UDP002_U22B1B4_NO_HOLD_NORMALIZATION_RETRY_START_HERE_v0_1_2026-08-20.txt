UDP002 U22B1B4：NONE Hold 语义规范化与受控重跑
版本：v0.1
日期：2026-08-20

一、这一步为什么存在

U22B1B3 已经确认真实配置为：

- CAMERA_1_DISTANCE：HoldPolicy = NONE，MaxAgeFrames = 空白
- CAMERA_3_DISTANCE：HoldPolicy = NONE，MaxAgeFrames = 空白

S1 执行接口要求 MaxAgeFrames 必须是非负整数，因此原 Run 按 fail-close
原则停止。B1B4 不修改原 B1B3 失败 Run，也不修改已经验收的 S1 算法模块。
它在配置边界执行唯一获批的确定性规范化：

    HoldPolicy = NONE 且 MaxAgeFrames 为空
    -> MaxAgeFrames = 0（integer）

工程含义：不允许跨 Frame 保持；只有当前 Frame 的实际更新可用。

从 public 中转仓库下载以下三个文件，全部放到：

    C-CODE\U-UDP002\04_TEMP

文件：

1. UDP002_U22B1B4_NO_HOLD_NORMALIZATION_RETRY_START_HERE_v0_1_2026-08-20.txt

3. udp002_u22b1b4_no_hold_normalization_retry_acceptance_v0_1.py.txt

不要移动、覆盖或删除原 U22B1B3 的失败 Run 与诊断文件。

三、标准执行（Windows CMD，当前目录为 C-CODE）

python .\U-UDP002\04_TEMP\udp002_u22b1b4_no_hold_normalization_retry_acceptance_v0_1.py.txt --accept --workspace-root .\U-UDP002

Acceptance 会自动完成：

1. foundation audit；
2. runner self-test；
3. 读取已验收的 B1B2 S1 配置；
4. 把 NONE + blank 规范化为 integer 0；
5. 生成独立 v0.2 Binding Profile 与 Module Configuration；
6. 创建新的 U22B1B4_... Run，不修改 B1B3；
7. 执行 S0 -> S1；
8. 验证 lineage、Artifact、行语义与输入不变性；
9. 生成 plot view 与 U003 semantic review queue。

四、回传

只回传终端最后一行，不要手敲 JSON。

成功格式：

    U22B1B4 N-F...-V...-S...-Q...-N2-P1-X0 C-0

其中 N2 表示 C1/C3 两条 binding 均完成 NONE + blank -> 0 规范化。

失败格式：

失败时不要修改原 Run。完整诊断保存在：

    U-UDP002\04_TEMP\u22b1b4_acceptance_diagnostic_v0_1.json

诊断证据应包含失败字段、实际值、期望约束、来源阶段与首要排查动作。

技术成功标准：C-0，且 N2。

本节点只证明配置语义、执行链、Artifact 和 lineage 正确。它不证明 Camera
