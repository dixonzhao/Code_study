1. PURPOSE

U21D creates a deterministic software Module Plan by joining:

  fresh U21B static Registry eligibility
  + accepted U21C dynamic activation evidence
  + engineer-selected exact Module identities
  + declared artifact dependencies and output-conflict rules

U21D answers:

  "Which exact, already-qualified Module versions may be arranged into one
   structurally coherent S0-S7 software plan?"

It does not answer whether required CAN signals exist in a particular U001
package, does not run production Module code and does not process company data.


2. CURRENT THREE-LAYER FOUNDATION

U21A Engine
  Owns Run lifecycle, directories, diagnostics and S0-S7 state.

U21B Registry
  Performs static no-execution Module discovery and classification.

U21C Activation Controller
  Performs one exact Manifest-declared Module self-test and writes identity-
  bound activation evidence.

U21D
  Joins those facts into an ordered software plan without executing the plan.

4. REQUIRED CLI MODES

4.1 Internal integration self-test

  --self-test
  --registry-program PATH
  --activation-controller PATH
  --schema-bundle PATH
  --contract-validator PATH
  --fixture-manifest PATH

4.2 Resolve one software plan

  --resolve-plan
  --modules-root PATH
  --activation-evidence-dir PATH
  --engine-version MAJOR.MINOR.PATCH
  --registry-program PATH
  --schema-bundle PATH
  --contract-validator PATH
  --select MODULE_ID@MAJOR.MINOR.PATCH
  --out PATH

--select is repeatable and at least one selection is required.

Exactly one action mode is required. Controlled exits:

  0 = complete SOFTWARE_PLAN_READY output written
  7 = controlled plan denial or validation failure


5. SOFTWARE PLAN IS NOT RUN READINESS

U21D validates software identities, activation evidence, Stage order, artifact
dependencies and output conflicts.

RequiredInputs and OptionalInputs contain signal requirements that can be
resolved only against a specific U001 Signal Catalog and engineer selection.
U21D must preserve these requirements but report:

  SignalBindingStatus = DEFERRED_TO_RUN_PREFLIGHT

Therefore U21D success means SOFTWARE_PLAN_READY, not RUN_READY. A later node
will bind the plan to U001 D3 Signal Catalog and Run configuration.


6. FRESH REGISTRY JOIN

For every --resolve-plan request:

1. invoke the accepted Registry through sys.executable and --scan;
2. create the Registry Snapshot in a TemporaryDirectory;
3. require Registry exit 0 and a parseable complete snapshot;
4. compute Registry program and snapshot SHA-256;
5. for every --select identity, require exactly one matching Registry entry;
6. require RegistryStatus == SELFTEST_REQUIRED;
7. reject duplicate --select identities;
8. load and validate the exact Manifest through the frozen Validator;
9. recompute Manifest, implementation and configuration hashes;
10. require equality with the fresh Registry entry.

Do not import or execute Module implementation during resolution.


7. ACTIVATION EVIDENCE JOIN

Recursively inspect only files named with a .json suffix under the selected
activation evidence directory. Do not import code from that directory.

An activation evidence record is eligible only when:

- EvidenceType == U002_MODULE_SELFTEST_EVIDENCE;
- EvidenceVersion == 0.1;
- ActivationPolicyVersion == U21C-0.1;
- ActivationStatus == SELFTEST_ACCEPTED;
- EngineVersion equals requested EngineVersion;
- ModuleId and ModuleVersion equal the selected identity;
- ManifestSha256 equals the fresh Registry/Manifest hash;
- ImplementationSha256 equals the fresh implementation hash;
- ConfigurationSchemaSha256 equals the fresh configuration hash;
- RegistryProgramSha256 equals the currently supplied Registry program hash;
- TokenMatched is true;
- TimedOut and OutputLimitExceeded are false;
- ShellUsed is false;
- ArgumentsPolicy == MANIFEST_DECLARED_ONLY.

Compute and record the exact evidence-file SHA-256.

If multiple eligible accepted records bind the same exact identity, select
deterministically by:

  GeneratedAtUtc descending, then evidence relative path ascending.

Record other matching accepted evidence as superseded warnings. Invalid,
failed or stale evidence must never qualify a Module.


8. MODULE ORDER

The fixed Stage order is:

  S0, S1, S2, S3, S4, S5, S6, S7

First group Modules by Stage order. Within a Stage, resolve declared artifact
dependencies before dependents where possible. Final deterministic tie-break:

  ModuleId, ModuleVersion, ManifestRelativePath

No selected Module may depend on an Artifact produced only by a later Stage.

Cycles in the artifact dependency graph are forbidden.


9. ARTIFACT REQUIREMENT MATCHING

A RequiresArtifacts item matches a ProvidesArtifacts item when:

- ArtifactType is equal;
- ArtifactSchemaId is equal;
- provided ArtifactSchemaVersion is numerically greater than or equal to
  MinimumSchemaVersion.

Apply Cardinality:

  ONE          exactly one selected provider required
  ZERO_OR_ONE  zero or one provider allowed
  ONE_OR_MORE  at least one provider required
  ZERO_OR_MORE any number allowed

Numeric semantic version comparison is required. Do not compare version strings
lexically.


10. OUTPUT AND CONFLICT RULES

Reject the plan when:

- two selected Modules have the same OutputNamespace;
- more than one selected provider declares ExclusiveOutput=true for the same
  ArtifactType plus ArtifactSchemaId;
- an Artifact requirement cardinality is violated;
- a required provider occurs in a later Stage;
- the artifact dependency graph contains a cycle;
- a required selected Module lacks current activation evidence;
- selected identity is duplicated or ambiguous.

ConflictPolicy does not permit latest-writer-wins. REQUIRE_ARBITRATION means an
explicit selected ARBITRATION Module must consume non-exclusive candidate
Artifacts and provide a distinct canonical Artifact. U21D must not invent an
implicit arbitration rule.


11. REQUIRED OUTPUT PLAN

Write one UTF-8 JSON object atomically using a sibling temporary file and
os.replace. Sort keys and non-semantic lists for stable structure.

Top-level fields:

  PlanType = U002_QUALIFIED_MODULE_PLAN
  PlanVersion = 0.1
  GeneratedAtUtc
  PlanStatus = SOFTWARE_PLAN_READY
  EngineVersion
  RegistryProgramSha256
  RegistrySnapshotSha256
  ModulesRootIdentity
  SignalBindingStatus = DEFERRED_TO_RUN_PREFLIGHT
  SelectedModuleCount
  SelectedModules
  ExecutionOrder
  ArtifactGraph
  UnresolvedSignalInputs
  EvidenceBindings
  Warnings

Each SelectedModules entry must contain:

  PlanOrder
  ModuleId
  ModuleVersion
  DisplayName
  Stage
  ModuleKind
  AlgorithmStatus
  ExecutionRequirement
  ManifestRelativePath
  ManifestSha256
  ImplementationSha256
  ConfigurationSchemaSha256
  ActivationEvidenceRelativePath
  ActivationEvidenceSha256
  OutputNamespace
  RequiredInputs
  OptionalInputs
  RequiresArtifacts
  ProvidesArtifacts
  FailurePolicy
  ConflictPolicy

ExecutionOrder is an ordered list of ModuleId plus ModuleVersion identities.

ArtifactGraph records every requirement-provider edge and its schema version.

UnresolvedSignalInputs preserves required/optional input declarations by Module
for later U001 Signal Catalog binding.

EvidenceBindings must make every selected software and activation identity
traceable. Do not include raw CAN rows, DBC content or company signal values.


12. CONTROLLED PLAN DENIAL

On denial, return exit 7 and print one short stable line. Do not write a partial
SOFTWARE_PLAN_READY output.

Stable reasons include:

  SELECT_PARSE
  DUPLICATE_SELECTION
  MODULE_NOT_FOUND
  MODULE_STATIC_NOT_ELIGIBLE
  ACTIVATION_EVIDENCE_MISSING
  ACTIVATION_EVIDENCE_STALE
  ARTIFACT_REQUIREMENT_UNSATISFIED
  ARTIFACT_CARDINALITY
  LATER_STAGE_DEPENDENCY
  ARTIFACT_CYCLE
  OUTPUT_NAMESPACE_COLLISION
  EXCLUSIVE_OUTPUT_COLLISION
  REGISTRY_FAILED
  EVIDENCE_INVALID


13. INTERNAL INTEGRATION SELF-TEST

Use tempfile.TemporaryDirectory and do not modify accepted inputs.

Create three synthetic Python Module Packs forming this valid chain:

  M1 S1 semantic builder
     provides non-exclusive SYNTHETIC_SEMANTIC artifact

  M2 S4 baseline
     requires SYNTHETIC_SEMANTIC ONE
     provides exclusive SYNTHETIC_BASELINE artifact

  M3 S7 exporter
     requires SYNTHETIC_BASELINE ONE
     provides exclusive SYNTHETIC_HANDOFF artifact

For M1-M3:

- derive valid Manifests from the accepted fixture;
- create real implementation/configuration files and exact hashes;
- call the accepted U21C Activation Controller through its public CLI;
- require three accepted activation evidence files;
- then resolve one plan through the same production resolver path.

The self-test must cover at least:

1. three exact qualified Modules accepted;
2. deterministic S1 -> S4 -> S7 execution order;
3. complete artifact edges;
4. unresolved signal requirements preserved;
5. missing activation evidence denied;
6. stale implementation binding denied;
7. requested Engine mismatch denied;
8. unsatisfied artifact requirement denied;
9. duplicate selection denied;
10. exclusive output collision denied;
11. later-Stage provider denied;
12. repeated plan stable after excluding GeneratedAtUtc and Registry Snapshot
    timestamp/hash;
13. no production Module marker created;
14. atomic output is complete and parseable.

Perform exactly 24 named assertions and print only:

  U21D1 N-T24-M3-O3-F6-D1-P1-X0 C-0

Meanings:

  T24 = 24 named assertions passed
  M3  = three exact qualified Modules joined
  O3  = deterministic three-Module order passed
  F6  = six representative invalid plans denied
  D1  = stable plan projection repeatability passed
  P1  = no production Module callable executed
  X0  = no uncontrolled exception

On failure print only:

  U21D1-ERROR-<STABLE_REASON> C-7
