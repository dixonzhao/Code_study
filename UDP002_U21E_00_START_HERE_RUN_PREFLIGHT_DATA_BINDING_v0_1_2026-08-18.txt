1. PURPOSE

U21E binds one already-qualified U21D software plan to one immutable U001
CONTROLLED_PROFILE six-file package and one explicit engineer Run Request.

It answers:

  "Do the exact selected Modules, U001 package, signals, configurations,
   FrameCount range and Run purpose form one complete RUN_PREFLIGHT_READY
   configuration?"

U21E performs metadata, identity, schema, quality and binding work only. It does
not calculate discrepancy, baseline, residual, correlation or candidates. It
does not execute a production Module callable and does not modify U001 files.


2. POSITION IN THE FOUNDATION

U21A  governed Run lifecycle and S0-S7 workspace
U21B  static Module eligibility
U21C  controlled Module self-test evidence
U21D  deterministic SOFTWARE_PLAN_READY plan
U21E  plan + U001 package + signal/config/scope -> RUN_PREFLIGHT_READY
U21F  controlled Stage execution
U21G  independent synthetic vertical acceptance and foundation freeze

U21E is a control-plane binder. It is not an analysis Stage and must not be
implemented as S0 algorithm code.

4. MVP INPUT MODE BOUNDARY

U21E v0.1 accepts only:

  CONTROLLED_PROFILE six-file U001 package

It does not consume AUTO_DISCOVERY shards in v0.1. This is a deliberate MVP
boundary, not removal of broad 700-variable screening from the U002 roadmap.
AUTO_DISCOVERY remains a later sharded screening adapter and must not be faked
by concatenating all shards into one wide in-memory table.

The controlled package contains:

  D1 u001_decoded_updates.csv
  D2 u001_frame_values.csv
  D3 u001_signal_catalog.csv
  D4 u001_quality_report.csv
  D5 u001_run_manifest.json

U21E v0.1 machine binding consumes D2/D3/D4/D5. It records D1 and D6 presence
but does not read their payloads. D1 is reserved for a later UPDATE_DOMAIN
adapter; D6 is human-facing and cannot prove machine-input integrity.

6. RUN REQUEST CONTRACT

The run-request input is one UTF-8 JSON object with this logical structure:

  RequestType = U002_RUN_PREFLIGHT_REQUEST
  RequestVersion = 0.1
  CaseId
  RunPurpose
  Scope
  ClockDomain
  InputBindings
  ResolvedConfigurations
  Notes

RunPurpose is one of:

  SMOKE
  TUNING
  EVALUATION
  PREVIEW

Scope contains:

  ScopeType = FULL_CASE or FRAME_RANGE
  FrameStart = integer or null
  FrameEnd = integer or null
  RangeReason = non-empty string
  SelectionSource = ENGINEER / TEST_PLAN / PREDEFINED_RULE
  SelectedBeforeResults = boolean

FULL_CASE requires null FrameStart and FrameEnd; U21E resolves them from valid
U001 quality/manifest evidence. FRAME_RANGE requires nonnegative integers,
FrameStart <= FrameEnd and both inside the declared U001 frame domain.

FILTERED_RANGE is not implemented in v0.1 because frozen U2-0A RunScope v0.1
does not yet contain that value. Do not silently encode it as FRAME_RANGE.

EVALUATION requires SelectedBeforeResults=true. Otherwise deny preflight.

ClockDomain contains:

  ClockKind = FRAMECOUNT
  ClockDomainId
  FrameRateHz = positive number or null
  TimeUnit = frame

The current case normally uses 20 Hz, but U21E must record the supplied and
upstream-declared evidence rather than hard-code 20 for all future datasets.


7. INPUT BINDING CONTRACT

InputBindings is an array. Each entry contains:

  ModuleId
  ModuleVersion
  PortId
  SelectionMode
  CanonicalNames

SelectionMode is:

  EXPLICIT       CanonicalNames must contain one or more engineer-selected names
  ALL_MATCHES    CanonicalNames must be empty; bind every eligible D3 match
  NONE           optional port only; CanonicalNames must be empty

There must be exactly one binding request for every RequiredInputs port.
OptionalInputs ports may be omitted; omission is normalized to NONE and must be
recorded in the output.

This design supports two safe workflows:

- a precise Camera/Radar role binding through EXPLICIT;
- a broad, Module-governed candidate set through ALL_MATCHES without manually
  typing hundreds of CanonicalName values.

ALL_MATCHES does not override MinCount or MaxCount. If the eligible count
violates the port cardinality, preflight is denied rather than truncated.


8. SIGNAL SELECTOR MATCHING

For one input port:

- fields inside one Selector are logical AND;
- multiple Selectors are logical OR;
- a bound signal must match at least one port Selector;
- when ScopeSelector.SignalSelectors is non-empty, it must also match at least
  one Module ScopeSelector;
- CanonicalName matching is exact and case-sensitive;
- Channel is integer equality;
- CAN ID is numeric equality after safe hexadecimal/decimal normalization;
- MessageName and SignalName are exact;
- Unit is exact after outer whitespace removal and remains case-sensitive;
- SignalRole is exact;
- duplicate CanonicalName catalog rows are blocking.

U001-to-U002 ValueKind bridge for v0.1:

  U001 FLOAT or INTEGER  -> U002 NUMERIC
  U001 BOOLEAN           -> U002 BOOLEAN
  U001 ENUM              -> U002 ENUM
  U001 BITFIELD          -> U002 FLAG

Other or unknown ValueKind values do not match a typed selector unless the
selector leaves ValueKind null. Preserve a warning; do not guess.


9. D2/D3 SIGNAL BINDING REQUIREMENTS

For every bound CanonicalName:

- exactly one D3 row exists;
- IncludeInFrameView is true;
- WithinFramePolicy is not KEEP_STREAM_ONLY for this FRAME_DOMAIN binder;
- Unit, ValueKind, SignalRole, HoldPolicy and MaxAgeFrames are present or an
  explicit warning/denial policy is recorded;
- D2 header contains the exact seven-column group:

    S__value
    S__label
    S__updated
    S__update_count
    S__age
    S__valid
    S__missing_reason

- U21E records the exact column mapping in binding evidence;
- U21E never substitutes `notna(S__value)` for S__valid;
- U21E never converts blank/NaN to zero;
- U21E never invents an unlimited forward fill;
- VALID_CARRIED remains usable only under D3 HoldPolicy/MaxAgeFrames and later
  Module logic. Preflight records the policy but does not reinterpret values.

Read only the D2 header during U21E. Do not load or scan the full signal payload.
Frame-domain bounds and quality are taken from accepted D4/D5 evidence.


10. U001 PACKAGE PREFLIGHT

Require all six standard basenames. Reject ambiguous duplicate standard files.

For D3:

- require the Unified Data Contract v0.1 required columns;
- reject duplicate/blank CanonicalName;
- parse booleans and integers strictly;
- keep original metadata text in the evidence projection.

For D4:

- accept the tidy Scope,CanonicalName,Metric,Value,Unit,SourceGate,Status,Notes
  representation;
- require global package/blocking status to pass;
- require numeric FrameCount evidence;
- require no canonical duplicate/out-of-order/non-numeric FrameCount error;
- deny required-input signal dtype conversion failure or blocking status;
- allow optional-signal exclusion only when the reason is explicit.

For D5:

- require parseable complete successful CONTROLLED_PROFILE identity;
- require DatasetId, RunId, SegmentId, SourceId and contract/profile identity;
- require FrameCount source/assignment definition;
- require declared relative output identities and no company absolute paths;
- reject an incomplete/failed package;
- compute and record exact byte SHA-256 for D2, D3, D4 and D5;
- compare D5-declared D2/D3/D4 identities when those declarations exist;
- record D1/D6 as present but UNCONSUMED_BY_U21E_V0_1.

Do not rerun U001 algorithms. U21E verifies the accepted package boundary and
binds it; it is not a second U001 validator.


11. SOFTWARE PLAN AND MODULE IDENTITY PREFLIGHT

Require:

  PlanType = U002_QUALIFIED_MODULE_PLAN
  PlanVersion = 0.1
  PlanStatus = SOFTWARE_PLAN_READY
  SignalBindingStatus = DEFERRED_TO_RUN_PREFLIGHT

Compute the software-plan SHA-256.

For every SelectedModules entry:

- resolve ManifestRelativePath strictly below --modules-root;
- reject absolute path and parent traversal;
- recompute Manifest, implementation and configuration-schema hashes;
- require exact equality with the U21D plan;
- require ExecutionOrder and PlanOrder consistency;
- do not import or execute implementation code.

The currently frozen U21D plan is immutable input. U21E may add binding evidence
but must not rewrite SelectedModules or silently reorder the plan.


12. MODULE CONFIGURATION BINDING

ResolvedConfigurations is an object keyed by:

  ModuleId@ModuleVersion

Every selected Module requires exactly one configuration object, including an
empty object when the schema permits it.

Load the exact configuration schema declared and hashed by the Module Manifest.
U21E v0.1 implements a dependency-free JSON Schema subset sufficient for MVP:

- type: object, array, string, integer, number, boolean, null;
- properties, required, additionalProperties;
- enum, const;
- minimum, maximum, exclusiveMinimum, exclusiveMaximum;
- minLength, maxLength, pattern;
- minItems, maxItems, uniqueItems, items;
- nested objects and arrays.

Reject schemas containing unsupported behavioral keywords such as $ref, oneOf,
anyOf, allOf, not, if/then/else or unevaluatedProperties. Do not silently skip
unsupported schema logic.

Normalize JSON deterministically with sorted keys and compact separators, then
record ResolvedConfigSha256 for each Module.


13. REQUIRED OUTPUT

Write one atomic UTF-8 JSON object using a sibling temporary file and os.replace.
Stable lists and keys must be deterministic.

Top-level fields:

  PreflightType = U002_RUN_PREFLIGHT_BINDING
  PreflightVersion = 0.1
  GeneratedAtUtc
  PreflightStatus = RUN_PREFLIGHT_READY
  EngineVersion
  CaseId
  RunPurpose
  SoftwarePlanIdentity
  U001PackageIdentity
  RunRequestSha256
  ResolvedScope
  ResolvedClockDomain
  ResolvedModules
  SignalBindings
  ResolvedConfigurations
  FrameTableBinding
  QualityDecision
  Warnings

SoftwarePlanIdentity records plan SHA-256, Registry program/snapshot identities
and the exact selected software identities.

U001PackageIdentity records DatasetId, upstream RunId, SegmentId, SourceId,
contract/profile identity, D2-D5 hashes and standard file roles.

ResolvedModules preserves U21D order and records each Manifest/implementation/
configuration-schema/evidence identity plus ResolvedConfigSha256.

SignalBindings records required/optional status, selection mode, port
cardinality, selector projection, CanonicalName list, D3 semantic projection and
exact D2 seven-column mapping.

FrameTableBinding records D2 relative basename, FrameCount column, upstream
frame bounds, selected frame bounds and FRAME_DOMAIN limitations.

The output is preflight evidence, not the final frozen U002 Run Manifest. U21F
later uses it to initialize and execute one governed Run.


14. DENIAL CONDITIONS

At minimum deny with stable reason codes for:

- invalid/not-ready/stale software plan;
- Module or schema identity mismatch;
- missing/failed/ambiguous U001 six-file package;
- D3 duplicate identity or missing required columns;
- D4 blocking quality or FrameCount failure;
- D5 failure, identity mismatch or unsafe path;
- missing D2 seven-column signal group;
- required port missing, ambiguous or outside MinCount/MaxCount;
- explicit CanonicalName not eligible for its selector;
- unsupported UPDATE_DOMAIN/KEEP_STREAM_ONLY binding;
- invalid RunScope or out-of-domain frame range;
- EVALUATION selected after inspecting results;
- missing/extra/invalid Module configuration;
- unsupported configuration-schema keyword;
- existing output path;
- any attempted parent traversal or absolute persisted path.

No latest-file guessing, fuzzy CanonicalName matching or best-effort fallback is
allowed.


15. INTERNAL SELF-TEST - 24 CHECKS

The self-test creates only temporary synthetic files and must cover:

  controlled six-file package, exact explicit binding, deterministic repeated
  output stable projection.

U6 U001 boundary
  six-file presence, D3 duplicate, D4 blocking quality, D5 failure/path safety,
  D2 header group and non-reading of D1/D6 payloads.

  explicit success, all-matches success, required missing, cardinality overflow,

  valid empty/nonempty config, missing required property, extra property and

S2 scope
  FULL_CASE resolution and valid FRAME_RANGE plus denied out-of-range evidence.

Also prove:

- no production Module implementation is imported/executed;
- no mathematical analysis result is created;
- output is atomic and existing output is not overwritten;
- uncontrolled exception count is zero.
