======================================================================
4. END-TO-END BOUNDED MEMORY ARCHITECTURE
======================================================================

4.1 Allowed long-lived state

Long-lived in-memory state may be proportional only to fixed architecture
dimensions, not dataset length:

- 69 message payload-cache entries;
- 705 candidate signal states and quality counters;
- one open FrameCount aggregation state;
- deterministic catalog/config/DBC definitions;
- fixed-size writer buffers described below;
- small capped diagnostic example lists, maximum 20 per category.

4.2 Forbidden accumulators

The following are forbidden:

- one global list of every update record;
- one list/DataFrame per batch that grows until end-of-run;
- one global list of every finalized frame;
- reading completed shard files back into memory to construct the manifest;
- concatenating all source chunks or all output shards;
- retaining pandas chunk objects after their chunk is processed;
- keeping per-row debug objects without a strict cap.

4.3 Incremental update writers

Create all deterministic shard headers once in a temporary sibling output
directory.  Maintain a bounded update buffer for each BatchId.

Required defaults:

- update_buffer_rows_per_batch = 256;
- total pending update rows across all batches must never exceed
  batch_count * update_buffer_rows_per_batch = 5,888 for B23;
- when one batch buffer reaches 256, append its rows in one block and clear the
  same list immediately;
- flush all remaining buffers at normal completion;
- record observed maximum per-batch and total pending rows.

Use deterministic csv writing.  A DataFrame may be created only from one fixed
buffer immediately before append and must be deleted after append.  Direct
csv.writer block writing is preferred when it preserves accepted formatting.

4.4 Incremental frame writers

Finalize one FrameCount at a time.  Create one frame row per BatchId from the
current frame state, then append through fixed-size batch buffers.

Required defaults:

- frame_buffer_rows_per_batch = 32;
- total pending frame rows across B23 must never exceed 736;
- clear each batch frame buffer immediately after append;
- never retain all FrameCount rows for later DataFrame construction;
- all frame shards must retain the same strict FrameCount sequence.

4.5 Streaming counts, hashes and manifest

Maintain row counts as integers while writing.  After all writers close, compute
SHA-256 by streaming each completed file in binary chunks.  Never read a whole
artifact to hash it.  Build the manifest from counters and streamed hashes.

4.6 Resource cleanup and interruption

Use try/finally to close every writer.  On KeyboardInterrupt, MemoryError,
RSS-limit breach or another blocking exception:

- do not create the success capsule;
- do not atomically promote the temporary folder to the final output path;
- write a small ABORTED_RUN.txt in the temporary folder with category only;
- print one C-7 final line;
- release source chunks, writer buffers and handles;
- never repair or reuse the partial folder.

6. OUTPUT-CAPACITY FORECAST
======================================================================

Add mode:

--capacity-report

This mode operates on one completed bounded sample output and the known full
source-row count.  It must not load shard contents fully into memory.

Required inputs:

--sample-out
--full-source-row-count
--out
--max-projected-output-gb       default 20

Measure recursively and streamingly:

- sample source rows;
- sample update rows;
- sample frame rows;
- update-shard bytes;
- frame-shard bytes;
- metadata bytes;
- total bytes;
- projected full-source bytes using source-row scaling for update artifacts
  and observed/expected FrameCount scaling for frame artifacts;
- free disk bytes at requested full output root;
- safety ratio = free disk / projected output bytes.

Capacity passes only when:

- projected total output <= max projected output budget;
- free disk >= projected output * 1.5 + 10 GiB;
- all sample artifacts are contract-valid;
- no arithmetic/identity field is missing.

Capacity failure does not authorize silently omitting update shards or changing
serialization.  Return C-7 so Codex can decide whether Data Contract v0.2 is
required.

Required capacity capsule:

UDP001G10B1R5C N-S{sampleRows}-F{sampleFrames}-UR{updateRows}-FR{frameRows}-SB{sampleMiB}-PG{projectedGiB_rounded}-FG{freeGiB_rounded}-SR{safetyRatio_x100_rounded}-M{memoryBounded0or1}-X{errors} C-{code}

No company values, paths or signal names enter the capsule.
