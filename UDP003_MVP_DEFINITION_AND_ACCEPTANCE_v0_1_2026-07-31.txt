1. IDENTITY

Task ID:
  UDP003

Product name:
  U003 Evidence Review Workbench MVP

Accepted implementation candidate:
  FrameCount Video Reviewer v0.5
  framecount_video_reviewer_v0_5.py

The task identity, product identity and implementation filename are different
layers and must not be used interchangeably.

2. RESPONSIBILITY

UDP003 is the human-evidence endpoint of the analysis chain:

  U001 traceable data preparation
    -> U002 anomaly-candidate generation
    -> U003 synchronized video/CAN review and engineering disposition

U003 may also be used at the beginning of an investigation to inspect an
already-known FrameCount interval. That convenience does not make U003 an
anomaly detector.

3. INPUT CONTRACT

Required for normal video review:
  - Local AVI/MP4/MOV/MKV/WMV/MPG/MPEG video.
  - Manually defined video-frame to CAN-FrameCount anchor.

Optional Event Queue CSV:
  - Start FrameCount column.
  - End FrameCount column.
  - Optional Event ID, existing review code and memo.

Optional Review Data CSV:
  - One identifiable FrameCount column.
  - One or more human-review signal columns.
  - The supplied CSV owns the visible schema; U003 retains all supplied columns
    and moves FrameCount to the first visible position.

Inputs are treated as read-only. U003 creates new output files and does not
rewrite the video, Event Queue or Review Data CSV.

4. OUTPUT CONTRACT

U003 may create:
  - Frame screenshot PNG at the displayed position.
  - One plot-ready CSV around the lag-adjusted yellow CAN row.
  - Full review-result CSV containing EventID, start/end FrameCount, review
    result and memo.
  - Compact review return-code TXT.

The plot-ready CSV contains every column loaded from the Review Data CSV and a
user-selected asymmetric Before/After FrameCount interval.

5. ACCEPTED MVP CAPABILITIES

  A. Video open and exact frame navigation.
  B. 1:1 and rate-based FrameCount mapping.
  C. Seek, single-frame stepping, speed control and Event loop.
  D. Event Queue loading, filtering, start/end navigation and in-GUI addition.
  E. Independent synchronized CAN table with all supplied review columns.
  F. Configurable CAN highlight lag and nearest-row indication.
  G. Asymmetric plot-window CSV export around the yellow row.
  H. Review code, multi-line memo, review export and screenshot.

6. EXPLICIT NON-RESPONSIBILITIES

U003 does not:
  - decode raw CAN or apply DBC;
  - clean, hold, impute, stitch or semantically validate signals;
  - select the active Camera target;
  - calculate Camera-Radar discrepancy, baseline or residual;
  - generate anomaly candidates;
  - decide root cause;
  - prove which sensor is correct;
  - modify U001 or U002 outputs.

7. KNOWN LIMITATIONS

  - Initial video/CAN mapping requires a user-confirmed anchor.
  - Lag is an explicit review setting, not an automatically estimated truth.
  - Nearest CAN row may be highlighted when the exact FrameCount is absent.
  - Duplicate Review Data FrameCounts retain the final row.
  - Video decode accuracy depends on the local OpenCV backend and codec.
  - Current delivery is a governed Python-source MVP, not a portable packaged
    executable. Packaging is deferred and does not block source-MVP acceptance.

8. ACCEPTANCE STRUCTURE

A1 - Independent non-GUI acceptance:
  - canonical source identity;
  - Python syntax;
  - required class/function/method surface;
  - helper, mapping and review-table behavior using temporary generic fixtures.

A2 - Visible GUI acceptance on the company computer:
  - two windows open;
  - real video and mapping work;
  - Event navigation works;
  - Review Data columns appear;
  - lag changes the yellow-row target;
  - plot CSV, review output and screenshot are created.

Existing field evidence from FVR001 is retained as development evidence but is
not silently rewritten as UDP003 acceptance evidence.
