UDP002 U22B21C 执行指南
日期：2026-08-26

一、这一步做什么

B21C不重新分析数据，也不修改已经通过的S7 Review Package或B21A
Handoff Descriptor。

它把U002连接U003的方式从“识别某个版本源码文件名”改为“验证启动能力契约”：

- 当前Python源码继续可用；
- 以后打包成单文件EXE时使用同一个接口；
- 两者都接收：--handoff-descriptor <path>；
- U002记录并校验接口版本、启动类型、文件路径和SHA-256；
- U003文件名以后可以变化，U002不再依赖版本化文件名白名单。

二、运行前放置

1. 将ZIP解压后的5个文件直接放入：
   C-CODE\U-UDP002\04_TEMP
2. 将本指南也直接放入同一个04_TEMP。
3. 不要放入04_TEMP的子文件夹。
4. 从C-CODE目录打开CMD。

三、只运行以下三条CMD命令

python U-UDP002\04_TEMP\u002_u22b21c_u003_launcher_contract_installer_v0_1.py.txt --prepare --workspace-root U-UDP002

python U-UDP002\04_TEMP\u002_u22b21c_u003_launcher_contract_installer_v0_1.py.txt --self-test --workspace-root U-UDP002

python U-UDP002\04_TEMP\u002_u22b21c_u003_launcher_contract_installer_v0_1.py.txt --execute --workspace-root U-UDP002

Prepare会自动整理04_TEMP中过期内容，无需另跑清理命令。

四、成功时查看

Prepare应以C0结束，并显示U003能力已被探测、凭据已生成。

Self-test预期：

B21CST-N24-C16-D1937-U12-G10-LS-X0-C0

Execute的C、D数字来自已接受的实际Handoff，预期本案例为：

B21C-N16-D1937-U12-G10-LS-X0-C0

随后应出现：

1. U002 Analysis Workbench；
2. U003 Evidence Review Workbench；
3. U003自动载入16个Event；
4. 右侧同步CAN表自动载入。

请人工回传：

B21C-N...-C0
B21CV-O1-E16-T1-C0

其中：

- O1：U002与U003都正常打开；
- E16：U003显示16个Event；
- T1：右侧CAN Review Table已有数据。

五、失败时

只回传屏幕上的B21CE-...-C7短码；如需进一步诊断，再提供：

C-CODE\U-UDP002\04_TEMP\U22B21C_ERROR.txt

不要自行修改Model、GUI、U003源码、能力契约或Handoff Descriptor。
