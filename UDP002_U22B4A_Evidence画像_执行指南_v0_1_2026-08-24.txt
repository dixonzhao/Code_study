UDP002 U22B4A Evidence画像 执行指南
==================================

版本：v0.1
日期：2026-08-24

一、本节点做什么
----------------

B4A只读分析已经验收的S5 ROBUST_RESIDUAL_EVIDENCE Artifact。

它不会：

- 修改B3 Run；
- 重新拟合Baseline；
- 修改Residual或Evidence；
- 生成正式Event；
- 判断Root Cause。

它只回答：S5 score分布是什么样；阈值2、3、4、5分别会产生多少超阈值行和
多少时间窗口。这个结果将用于B4B制定S6 Candidate Policy。


二、需要的文件
--------------

下载以下文件到：

U-UDP002\04_TEMP

u002_u22b4a_evidence_profiler_v0_1.py.txt


三、执行前检查
--------------

在C-CODE目录使用CMD：

if not exist U-UDP002\04_TEMP\u002_u22b4a_evidence_profiler_v0_1.py.txt echo MISSING-PROFILER

if not exist U-UDP002\07_OUTPUT\U22B3_TC001_F41480_41750_V01\run_artifact_index_v0_1.json echo MISSING-B3-RUN

正常情况下不应出现MISSING。


四、运行Self-test
-----------------

python U-UDP002\04_TEMP\u002_u22b4a_evidence_profiler_v0_1.py.txt --self-test

成功：

B4A-ST-PASS-25 C-0

Self-test通过时不需要回传。


五、运行真实B4A画像
-------------------

python U-UDP002\04_TEMP\u002_u22b4a_evidence_profiler_v0_1.py.txt --workspace-root U-UDP002 --run-id U22B3_TC001_F41480_41750_V01 --output-json U-UDP002\04_TEMP\U22B3_TC001_F41480_41750_V01_b4a_evidence_profile_v0_1.json


六、检查输出存在
----------------

if not exist U-UDP002\04_TEMP\U22B3_TC001_F41480_41750_V01_b4a_evidence_profile_v0_1.json echo MISSING-B4A-JSON

正常情况下不应出现MISSING。


七、只需回传两行
----------------

第一行：

B4A N-R...-V...-I...-Q50-...-Q90-...-Q95-...-Q99-...-MAX-...-PF...-X0 C-0

第二行：

B4AT T2-... T3-... T4-... T5-... C-0

B4AT每组五个数字依次表示：

ExceedanceRows.StrictRunCount.Merge20WindowCount.Merge100WindowCount.LongestStrictRunRows

例如：

T3-8.4.3.2.3

表示score大于等于3的行有8个；严格连续段4个；允许20帧间隔后3个窗口；
允许100帧间隔后2个窗口；最长严格连续段3行。


八、失败处理
------------

失败时只回传：

B4AE K-原因-X1 C-7

不要修改B3 Artifact、Manifest、CSV或程序中的Threshold。
