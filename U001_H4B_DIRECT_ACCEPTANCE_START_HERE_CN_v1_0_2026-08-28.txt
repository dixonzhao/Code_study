U001 H4B 独立验收——公司电脑执行指南
版本：v1.0（2026-08-28）

目标
----
读取已通过验收的H4A Frame View，测量21个信号的真实更新节奏，并编译、执行当前正式的“无跨帧保持”策略。

为什么本轮全部设置为 NONE
-----------------------
Cadence只说明信号多久更新一次，不能自动证明旧值在下一帧仍然有效。
当前Golden Run先保留最严格、最可追溯的baseline：只有本帧真实出现的更新可用，不做forward fill。
将来某个信号确有业务依据时，再单独批准有限MaxAgeFrames，而不是从统计频率自动推断。

放置位置
--------
把下面文件放到：
C-CODE\U-UDP001\04_TEMP

文件：
u001_h4b_direct_acceptance_v1_0.py.txt

输入位置
--------
C-CODE\U-UDP001\04_TEMP\U1H4D_OUTPUT\h4a_package
C-CODE\U-UDP001\04_TEMP\U1H4D_OUTPUT\frame_policy

输出位置
--------
C-CODE\U-UDP001\04_TEMP\U1H4BD_OUTPUT

执行方法
--------
在CMD中进入C-CODE根目录，只执行以下三行：

python U-UDP001\04_TEMP\u001_h4b_direct_acceptance_v1_0.py.txt --prepare
python U-UDP001\04_TEMP\u001_h4b_direct_acceptance_v1_0.py.txt --self-test
python U-UDP001\04_TEMP\u001_h4b_direct_acceptance_v1_0.py.txt --execute

三步含义
--------
1. prepare：清理本阶段旧输出，并核对H4A、Frame Policy和三个H4B核心程序。
2. self-test：验证Cadence、Policy Compiler和Hold Engine的固定语义。
3. execute：统计更新节奏，明确批准21个NONE策略，生成H4B包并检查没有carry、stale、补零或合成帧。

通过标准
--------
只回传最终以 H4B- 开头、以 -X0-C0 结尾的一行。

失败处理
--------
只回传以 H4BE- 开头、以 -X1-C7 结尾的一行，不要手工修改核心程序。
