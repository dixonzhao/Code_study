6. SYNTHETIC MODULE PACKS

Use the accepted valid_module_manifest.json as a read-only base. Generate
independent copies with real hashes for implementation and configuration
schema. Do not modify the accepted fixture.

Construct at least these Packs:

P1 PASS
  Python entrypoint recognizes --self-test, writes a self-test marker, prints
  the exact expected token as one line and exits with the declared code.
  If invoked without --self-test it writes a production marker. The production
  marker must never appear.

F1 TOKEN_MISSING
  Correct exit but no exact expected-token line.

F2 EXIT_MISMATCH
  Exact token but wrong exit code.

F3 TIMEOUT
  Sleeps longer than a one-second controller timeout.

F4 OUTPUT_LIMIT
  Writes more than the minimum permitted output limit.

B1 STATIC_DENIAL
  Entrypoint bytes do not match the declared ImplementationSha256. Include a
  marker that would prove accidental execution. The marker must remain absent.

B2 UNSUPPORTED_RUNTIME
  Contract-valid, hash-valid non-.py Entrypoint. Include a marker text but do
  not execute it.

Every Pack must have a unique ModuleId and valid ModuleVersion unless a test
specifically requires an identity mismatch.


7. POSITIVE ACCEPTANCE TEST

Run P1 twice through --activate-one into two different evidence files.

Independently require:

- both controller exits are 0;
- both ActivationStatus values are SELFTEST_ACCEPTED;
- exact expected token matching is true;
- observed exit code equals the Manifest declaration;
- no timeout or output-limit flag;
- ModuleId, ModuleVersion, Stage and relative Manifest path are correct;
- Manifest, implementation and configuration hashes equal independent Gate
  calculations;
- RegistryProgramSha256 equals independent Gate calculation;
- RegistrySnapshotSha256 is a valid lowercase SHA-256;
- ShellUsed is false;
- ArgumentsPolicy is MANIFEST_DECLARED_ONLY;
- RuntimePolicy is CURRENT_PYTHON_INTERPRETER;
- the self-test marker exists;
- the production marker does not exist.

Compare a stable projection of both accepted evidence records. Exclude only
GeneratedAtUtc, StartedAtUtc, CompletedAtUtc, DurationMilliseconds, temporary
absolute paths and RegistrySnapshotSha256 when its generated timestamp changes.
All remaining governed fields must agree.


8. FOUR DYNAMIC FAILURE TESTS

Run F1-F4 separately. Independently require controller exit 7 and complete,
parseable failure evidence.

Expected statuses:

  F1 SELFTEST_TOKEN_MISSING
  F2 SELFTEST_EXIT_MISMATCH
  F3 SELFTEST_TIMEOUT
  F4 SELFTEST_OUTPUT_LIMIT

No failure evidence may report SELFTEST_ACCEPTED. Timeout/output-limit children
must terminate, and retained diagnostic text must remain within the configured
bound.


9. TWO PRE-EXECUTION BLOCK TESTS

B1 must be denied by fresh U21B static precheck before Module execution. Its
marker must remain absent.

B2 must be denied as UNSUPPORTED_ENTRYPOINT before Module execution. No marker
or side effect may appear.

Both controller exits must be 7 and both evidence files must be parseable and
non-accepted.


10. THREE IDENTITY INVALIDATION TESTS

Start from a successful P1 activation evidence record and independently test:

I1 implementation mutation
  Change one Entrypoint byte without updating the Manifest. A new activation
  attempt must be rejected by static precheck.

I2 configuration mutation
  Change one Configuration Schema byte without updating the Manifest. A new
  activation attempt must be rejected by static precheck.

I3 requested identity mismatch
  Request a ModuleVersion different from the Manifest. Activation must be
  rejected because exactly one requested identity cannot be selected.

The original accepted evidence must not be treated as authorization for any
mutated or mismatched identity.


11. PRODUCTION-CALLABLE NON-EXECUTION

Across all tests, search every Gate-owned fixture directory for the production
marker. The count must be zero.

This is the black-box proof that U21C ran only Manifest.SelfTest.Arguments and
did not invoke the Entrypoint.Callable production path.

13. FORMAL SUCCESS CAPSULE

After all independent assertions pass, print only:

  U21CG1 N-R2-A1-F4-B2-I3-P1-X0 C-0

Meanings:

  R2 = two independent positive activation runs passed
  A1 = exact identity-bound positive Module accepted
  F4 = four dynamic failure modes correctly denied
  B2 = two pre-execution block modes correctly denied
  I3 = three identity invalidation tests passed
  P1 = production-callable non-execution proved
  X0 = no uncontrolled exception

On failure print only:

  U21CG1-ERROR-<STABLE_REASON> C-7

The detailed cause remains in Gate logs/evidence. Do not require the user to
transcribe hashes or long logs.
