U003 / U3M3B 高代码GUI组合执行指南
日期：2026-08-27

本步骤做什么
------------
U3M3B把原来集中在U003 v0.13单文件中的职责重新组合为：

  v0.14 Entry：启动参数、U002自动交接、顶层错误处理；
  GUI Shell：视频、同步CAN表、Event导航、Review与导出交互；
  Domain Core：Event、FrameCount映射、Return Capsule；
  Handoff Core：U002描述符和两个输入文件的SHA-256验收。

没有加载Module时，v0.14必须保持v0.13的既有行为。Module Manager尚未在
本步骤接入，将在U3M4单独实现，避免同时修改架构和业务功能。

Prepare阶段的TEMP清理
--------------------
Prepare会自动把U3M1、U3M2、U3M3A的旧中转文件和PREPARED目录移动到
U-UDP003\A-Archive。旧U3M3B_PREPARED也会先归档再重建。不会直接删除，
也不会移动本次正在执行的U3M3B ZIP和安装器。

下载位置
--------
把以下两个文件下载到：

  C-CODE\U-UDP003\04_TEMP

  UDP003_U3M3B_HIGH_CODE_COMPOSITION_v0_1.zip
  u003_u3m3b_high_code_composition_installer_v0_1.py.txt

ZIP无需手动解压。

执行
----
使用CMD进入C-CODE根目录，只执行以下三行：

  python U-UDP003\04_TEMP\u003_u3m3b_high_code_composition_installer_v0_1.py.txt --prepare
  python U-UDP003\01_PROGRAMS\u003_u3m3b_acceptance_gate_v0_1.py --self-test
  python U-UDP003\01_PROGRAMS\u003_u3m3b_acceptance_gate_v0_1.py --accept --open-gui --legacy U-UDP003\01_PROGRAMS\u003_evidence_review_workbench_v0_13.py

三行的意义
----------
第1行：清理旧TEMP、验证7个payload、确认v0.13基线未漂移并安装v0.14组合。
第2行：无界面执行127项回归检查；成功无需回传。
第3行：显示每项检查并打开v0.14 GUI。确认标题为
       “U003 Evidence Review Workbench v0.14”后，正常关闭窗口。

验收覆盖
--------
  67个GUI方法均存在；其中65个方法体与v0.13进行AST逐方法等价比较；
  2个FrameCount映射方法改为调用Domain Core，并用数值样例比较；
  UTF-8、CP932、Latin-1及逗号/分号/Tab读取行为比较；
  Event、Return Capsule、U002 Handoff和错误拒绝行为比较；
  v0.14在独立Python进程中重新导入并执行Self-test；
  最后由公司Windows主机完成真实GUI启动确认。

回传
----
关闭GUI后，只回传最后一行：

  U3M3B N-L1-G1-E1-D1-H1-M67-T128-X0 C-0

失败时回传完整U3M3BPE或U3M3BE错误行。

现实意义
--------
U3M3B完成U003向高代码模式的关键迁移：旧版仍作为冻结行为证据，新版不再把
所有逻辑塞在一个GUI文件中。后续新增Module Manager、双语Review Memo或
打包逻辑时，可以只修改自己的组件并运行自动回归，而不是重新人工验证整个程序。
