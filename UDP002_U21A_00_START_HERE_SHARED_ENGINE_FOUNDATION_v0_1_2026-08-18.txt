7. IMPLEMENTATION CONSTRAINTS

7.1 Runtime

- Python standard library only.
- Must work in the approved company Python environment from Windows CMD.
- No network access.
- No installation step.
- No source-data rows are read by U21A.

7.2 File and JSON rules

- UTF-8 without BOM.
- JSON keys sorted.
- Two-space JSON indentation.
- One LF at end of each text/JSON file.
- SHA-256 is calculated from exact persisted bytes.
- Use forward slashes inside manifest RelativePath fields.
- Never store absolute source paths in governed manifests or diagnostics.
- Do not use Python object hash() for identity.

7.3 Atomic persistence

Every governed JSON update must:

1. serialize the complete new document;
2. write sibling <name>.tmp bytes;
3. flush and fsync the temporary file;
4. replace the target with os.replace;
5. leave no accepted half-written JSON file.

7.4 Time

- Use timezone-aware UTC.
- Persist RFC 3339-compatible UTC text ending in Z.
- CreatedAtUtc never changes after Run creation.
- StartedAtUtc and CompletedAtUtc follow the frozen validator lifecycle.

7.5 Error handling

- Expected failures return exit code 7.
- Success returns exit code 0.
- Unexpected exceptions are caught at the outer boundary.
- A failure after Run creation must produce a failed Run Manifest and a
  Diagnostic Bundle whenever persistence remains possible.
- Do not silently continue after contract validation failure.
