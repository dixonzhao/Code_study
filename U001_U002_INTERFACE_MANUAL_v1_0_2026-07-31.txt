U001 -> U002 INTERFACE MANUAL
U002 输入输出契约手册
版本：1.0
日期：2026-07-31
适用上游：U001 Portable v0.2
基础契约：U001 Unified Data Contract v0.1
对象：不依赖 Codex、需要实现 U002 consumer 的外部程序员

======================================================================
0. 接口目标
======================================================================

本手册定义外部程序怎样安全消费 U001 输出，而不重新解释 U001 的数据语义。

U001 负责“数据准备事实”：

- source order；
- DBC decode；
- FrameCount assignment；
- canonical signal identity；
- unit/type/validity；
- update / aggregation / hold provenance；
- quality and run identity。

U002 负责“分析主动权”：

- 选择 outcome/reference/target；
- discrepancy/baseline/residual；
- 自动筛查 eligible variables；
- ranking/evidence；
- scenario/event/dynamic analysis；
- 输出少量可行动调查候选。

U002 必须把 U001 输出视为 immutable input。禁止原地改写。

======================================================================
1. 支持的接口模式
======================================================================

1.1 AUTO_DISCOVERY response（广域自动筛查）

用途：面对 700+ CAN variables，自动选择所有 technically eligible signals，
按 bounded-width shards 交给 U002。U001 只判断“能否解码/是否技术上可用”，不
判断“是否和 outcome 相关”。

U002 的入口：

  <RunRoot>/04_RESPONSE/u001_discovery_response_manifest.json

严禁：

- 扫描目录找最大的 CSV；
- 按修改时间找 newest file；
- 把 shards 合成一张 700-signal 全内存宽表；
- 绕过 response manifest 直接消费中间文件。

1.2 CONTROLLED_PROFILE 六文件包（正式可复现分析）

用途：shortlist 已由 U002 提议并经工程审批，signal semantics/policy 已明确。

六文件：

D1 u001_decoded_updates.csv
D2 u001_frame_values.csv
D3 u001_signal_catalog.csv
D4 u001_quality_report.csv
D5 u001_run_manifest.json
D6 u001_review_view.csv

U002 常规静态分析依赖 D2+D3+D4+D5；需要 update-domain 证据时读取 D1；D6 仅
用于人工理解或 U003，不可代替完整机器输入。

1.3 推荐闭环

  AUTO_DISCOVERY response
  -> U002 manifest/shard validation
  -> 自动 variable screening
  -> u002_signal_promotion_request.csv (PROPOSED)
  -> engineering approval
  -> new immutable CONTROLLED_PROFILE
  -> U001 rerun
  -> formal U002 analysis
  -> U003 review

逻辑文件：u001_discovery_request.json

主要必需字段：

- RequestSchemaVersion = U001_DISCOVERY_REQUEST_V0_1

- DatasetId
- RunId

- FrameKeyCANID
- FrameKeySignalName
- BatchSize
- ReusePolicy
- RequestedOutputRoot
- ExecutionPolicy
- SourceFingerprintExpected

当前 Frame Key：

  FrameKeyChannel = 2
  FrameKeyCANID = 0x620
  FrameKeySignalName = FrameCount

ExecutionPolicy 至少包含：

- ChunkSize
- MaxSourceRows（0 = full source）
- MaxAssignmentAgeRows
- MaxRssMiB
- UpdateBufferRows
- FrameBufferRows
- MemoryCheckEveryRows
- MinimumFreeGiB

Request 禁止包含 U002 算法参数，例如 correlation threshold、baseline method、
anomaly score、root-cause claim。

2.2 Response

正式运行目录：

  00_REQUEST/
  01_G1_CATALOG/
  02_PROFILE_CONFIG/
  03_DISCOVERY_DATA/
  04_RESPONSE/

response manifest：

  04_RESPONSE/u001_discovery_response_manifest.json

completion capsule：

  04_RESPONSE/u001_discovery_completion_capsule.txt

U002 只有在以下条件全部满足时才可读取：

- CompletionCode = 0；
- ReadyForU002 = 1；
- contract/request schema 是 U002 支持版本；
- request/response 的 DatasetId、RunId、RequestId 一致；
- FrameCount identity 与请求一致；
- manifest 声明的文件全部存在；
- SHA-256、row count、signal count 验证一致；
- blocking quality/error count = 0；
- output root 不是 incomplete folder；
- current input fingerprint 与 request/manifest 一致。

任一 blocking 条件失败：U002 必须 fail closed，不得“尽量读取”。

======================================================================
3. FrameCount 和样本域
======================================================================

3.1 FRAME_DOMAIN

用于：

- static discrepancy；
- distance baseline；
- residual/anomaly score；
- event localization；
- video-linked analysis。

主键：FrameCount。

要求：

- numeric；
- strictly increasing；
- canonical table 无 duplicate FrameCount；
- missing FrameCount gaps 不由 U001 自动补行；
- U002 不得重新排序或换成 CAN timestamp；
- 约 20 Hz，仅代表当前视频域。

3.2 UPDATE_DOMAIN

用于：真实 CAN signal update 序列、sub-frame update evidence、未来动态分析。

主顺序：SourceRowIndex / NativeSequence，带 assigned FrameCount。

限制：

- FrameCount 不能证明 sub-frame physical sampling interval；
- Source update order 不自动等于可信 physical time；
- 无可信 timestamp 时，SysID 只能使用明确的 20 Hz FRAME_DOMAIN，或以
  source-update/frame units 报告并声明限制；
- U002 不得凭 row index 推断 seconds、delay 或 gain dynamics。

4. D1 — u001_decoded_updates.csv
======================================================================

用途：真实 selected/eligible signal updates 的长表和追溯事实。

逻辑必需字段：

- SourceRowIndex
- SourceId
- SourceType
- ClockDomain
- NativeTimestamp
- NativeSequence
- FrameCount
- SyncKey
- SyncQuality
- FrameAssignmentStatus
- FrameAssignmentAgeRows
- CAN_ID
- Channel
- MessageName
- CanonicalName
- RawCode
- PhysicalValue
- ValueLabel
- ValueKind
- SignalRole
- Valid
- MissingReason
- MessageCounter
- SourceDateTime
- SourceTimeUs

约束：

- 一条 source message 可产生多条 signal update rows；
- SourceRowIndex 顺序必须保持；
- PhysicalValue 是解码值，不允许被 held/smoothed/fused 值覆盖；
- SourceDateTime/SourceTimeUs 可为空或不可信，只保留 provenance；
- assigned FrameCount 是 metadata assignment，不是 measurement forward fill；
- FrameAssignmentAgeRows 是从最后一个有效 FrameCount update 到该 source row 的
  行距，不是 signal 的 S__age。

U002 使用规则：

- 只把 Valid=true 的 measurement updates 作为默认数值样本；
- 仍保留 invalid rows 供质量/失效模式分析；
- 使用 CanonicalName，不用 display header 模糊匹配；
- 需要 unit/type/role 时 join D3，不从名字猜。

======================================================================
5. D2 — u001_frame_values.csv
======================================================================

用途：一行一个 canonical FrameCount 的机器分析主表。

固定 leading columns：

- FrameCount
- SourceRowFirst
- SourceRowLast
- SourceUpdateCount

每个 included signal S 使用固定 column group：

- S__value
- S__label
- S__updated
- S__update_count
- S__age
- S__valid
- S__missing_reason

字段语义：

S__value
  当前 frame 的 typed value。它可能来自 current-frame aggregation，也可能来自
  approved bounded hold；不能单独判断 freshness。

S__label
  enum/bitfield label；numeric signal 可为空。

S__updated
  当前 FrameCount 内是否发生至少一次真实 update。

S__update_count
  当前 FrameCount 内真实 updates 数量。

S__age
  距最后一个真实 valid update 的 FrameCount steps。
  0 = 本帧真实更新；正数 = carry/hold age；blank = 从未有可用 update。

S__valid
  当前 cell 是否被批准用于分析。U002 必须用它过滤，不能只判断 value non-null。

S__missing_reason
  解释 valid/missing/held/invalid 的 controlled status。

关键规则：

- U002 不得把 blank/NaN 变成 0；
- U002 不得忽略 S__age；
- `S__value` 相同不代表“payload 没更新”；结合 S__updated / S__update_count；
- held value 只有在 D3 HoldPolicy 和 MaxAgeFrames 允许且 S__valid=true 时可用；
- EVENT_FLAG 不应被 cross-frame hold；
- Boolean 0/false 默认是真实状态，不是 missing；
- missing FrameCount 不自动生成；
- high-rate IMU 若 policy=KEEP_STREAM_ONLY，可能没有 frame-level S__value，应读取 D1
  或等待批准的 resampling experiment。

推荐 U002 frame mask：

  usable_S = (S__valid == true)
             AND (S__missing_reason in approved valid states)
             AND (S__age <= D3.MaxAgeFrames when carried)

禁止仅使用：

  notna(S__value)

兼容保留字段可包括：SourceType、SourceAdapter、SourceFormat、ClockDomain、
CoordinateFrame、ReferencePoint、AxisConvention、OriginalUnit、CanonicalUnit、
UnitConversionRule、TopicName、MessageType、CalibrationVersion。

ValueKind 允许：

  FLOAT / INTEGER / BOOLEAN / ENUM / BITFIELD

SignalRole 允许：

  MEASUREMENT / STATE / EVENT_FLAG / VALIDITY_FLAG / COUNTER /
  IDENTIFIER / FRAME_KEY

UpdateMode 允许：

  PERIODIC / ON_CHANGE / EVENT / UNKNOWN

WithinFramePolicy 允许：

  LAST_UPDATE / FIRST_UPDATE / ANY_TRUE / BITWISE_OR /
  COUNT_UPDATES / KEEP_STREAM_ONLY

HoldPolicy 允许：

  NONE / HOLD_LAST_BOUNDED

U002 必须：

- 按 CanonicalName 建立 D2 group mapping；
- 按 ValueKind 分配兼容方法；
- 按 SignalRole 排除 counter/identifier/technical metadata 的不适当统计；
- 使用 Unit 做量纲检查；
- 不把 provisional metadata 当作 ground truth；
- 对 UNKNOWN semantics 保留 warning，不能擅自归类为 continuous measurement。

8. D5 — u001_run_manifest.json
======================================================================

用途：package identity、provenance、config identity 和 artifact registry。

至少包含：

- contract / implementation profile / schema version；
- ProcessingMode；
- DatasetId / RunId / SegmentId / SourceId；
- program/version；
- input basenames/sizes/fingerprints；
- DBC identities；
- selected/discovered profile identity；
- FrameCount source/assignment definition；
- validity/aggregation/hold policies；
- configuration fingerprint；
- declared output relative paths/hashes/counts；
- warnings；
- duration；
- success/failure status。

U002 必须把 manifest identity 连到自己的 run manifest 和每一个 candidate/event。

禁止：

- 使用 absolute company path 作为 dataset identity；
- 按 basename 以外的 workstation path 做 cache key；
- 忽略 config/source/DBC hash 复用旧数据；
- 修改 CSV 后保留旧 manifest。

Cache 复用仅在 source、DBC、profile、contract、frame key、batch/policy hashes 完全
一致时允许。由 U001 决定是否满足 reuse，不由 U002 猜测。

======================================================================

支持值：

- VALID_UPDATE

- VALID_CARRIED

- SOURCE_MISSING
- INCOMPLETE_BYTES
- DBC_INVALID_DEFAULT
- OUT_OF_DBC_RANGE
- USER_INVALID_RULE
- VALIDITY_FLAG_REJECTED
- STALE
- ASSOCIATION_AMBIGUOUS
- FRAME_UNASSIGNED
- UNKNOWN_ENUM_CODE
- NOT_APPLICABLE

U002 推荐分组：

Default usable:
  VALID_UPDATE, VALID_AGGREGATED，以及满足 policy/age 的 VALID_CARRIED。

Default unusable for numeric model fitting:
  其余状态。

但 unusable 不等于删除。它们可用于 dropout、invalidity 或数据质量 event 分析。

11. AUTO_DISCOVERY shard consumer
======================================================================

U002 不应要求 single monolithic 700-variable table。

推荐 consumer 流程：

1. 读取 response manifest；
2. 验证 identity、completion、quality 和 declared artifacts；
3. 读取 signal inventory / batch map；
4. 按 batch/shard 顺序逐个读取；
5. 每次只保留 frame key、outcome anchors 和当前 candidate batch；
6. 用 FrameCount join outcome；
7. 使用 valid/updated/age provenance；
8. 按 ValueKind/SignalRole 分组调用兼容 screening method；
9. 输出 candidate-level evidence，不输出因果结论；
10. 释放 shard 内存后读下一片；
11. 汇总 shortlist；
12. 产生 promotion request。

并发可以是 bounded parallel workers，但必须：

- 每个 worker 读取不同 shard；
- 输出顺序 deterministic；
- 相同输入生成相同结果；
- 不共享可变全局 DataFrame；
- 不改变 missingness / dtype / unit；
- 有 reference serial result 做 semantic equivalence test。

13. U002 最小结构验证伪代码
======================================================================

load response_manifest
assert CompletionCode == 0
assert ReadyForU002 == 1
assert supported_contract(response_manifest.ContractVersion)
assert identities_consistent(DatasetId, RunId, RequestId)

for artifact in response_manifest.DeclaredArtifacts:
    assert exists(artifact.RelativePath)
    assert sha256(file) == artifact.SHA256
    assert declared_counts_match(file)

load quality_report
assert blocking_error_count == 0
assert frame_key == (Channel=2, CAN_ID=0x620, Signal=FrameCount)

load signal_catalog
build canonical_name_registry
reject duplicate/unresolved canonical names

for each discovery_shard:
    load bounded shard
    assert FrameCount numeric/strictly_increasing/unique
    join outcome by FrameCount
    apply S__valid + S__missing_reason + S__age rules
    screen by ValueKind/SignalRole compatible method
    write candidate evidence
    release shard

write U002 run manifest linking SourceU001RunId and hashes

14. U002 必须拒绝的情况
======================================================================

- C-7 / CompletionCode != 0；
- ReadyForU002 != 1；
- incomplete run；
- missing response manifest；
- unsupported contract/schema；
- source/DBC/profile/config identity mismatch；
- missing/hash/row-count mismatch；
- FrameCount identity 错误；
- FrameCount duplicate/non-numeric/non-monotonic；
- required signal 没有 validity fields；
- held value 超过 MaxAgeFrames；
- blank-to-zero 或 unlimited forward fill 证据；
- unit/type/role/aggregation/hold 无法解析；
- U002 代码试图直接 import U001 private modules；
- 只存在 partial CSV 而没有完整 package evidence。

======================================================================
15. U001 与 U002 的禁止耦合
======================================================================

U002 不得：

- import U001 private Python modules；
- 自动点击 U001 GUI；
- 编辑 u001_g2/g4/g5/g6 control CSV；
- 在 U001 输出上做 in-place mutation；
- 把 U001 的 `latest folder` 当接口；
- 重新定义 FrameCount assignment；
- 重做 zero fill / forward fill；
- 把 Radar 默认称为 ground truth；
- 把 association strength 写成 causal effect；
- 将 Camera channel stitching 反写进 U001。

允许方向：

  U002/thin coordinator
  -> versioned U001 request
  -> public U001 command/controller
  -> exit code + manifest
  -> immutable artifact consumption

======================================================================
16. U002 应保留到下游的追溯字段
======================================================================

每个 U002 run、candidate、event window 至少应关联：

- SourceU001DatasetId
- SourceU001RunId
- SourceU001ContractVersion
- SourceU001ResponseManifestHash
- SourceProfileId / ProcessingMode
- FrameCount domain identity
- outcome/reference/target CanonicalName
- signal Unit / ValueKind / SignalRole
- validity/age policy used
- U002 Algorithm Card version
- threshold/model/config fingerprint

这样 U003 的视频结论才可追溯到 U001 数据身份和 U002 算法身份。

======================================================================
17. U002 MVP 接口成功标准
======================================================================

一个完整 U001 case 可以被 U002 读取，且 U002：

1. 结构验证通过；
2. 不丢失 missing/update/age provenance；
3. 明确选择 provisional reference/target 或 canonical camera signal；
4. 计算一个批准的 discrepancy/baseline/residual path；
5. 输出少量 start/center/end FrameCount candidate windows；
6. 输出 reviewer-compatible candidate_event_queue.csv 和 review_data.csv；
7. 每个结果能追溯到 U001 Run/Manifest/Profile；
8. 不声称自动 root cause。
