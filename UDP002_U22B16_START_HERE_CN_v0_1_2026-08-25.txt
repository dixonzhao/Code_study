UDP002 U22B16 执行指南
======================

为什么做B16
-----------
B15发现Radar无效率在5–10°最高，但之后下降，因此不是简单的“角度越大越容易丢失”。B16改用事件时间顺序，检查每个已验收Candidate中的：

失效前状态 → Radar失效开始 → 无效期间最大方位角 → 目标回到中心 → Radar重新捕获。

这样可以验证你在视频中观察到的“转弯后回正，Radar过若干Frame才恢复”，同时保留正前方短时丢失的特殊对照。

2°和5°仍只是B15统计分组边界，不是正式Radar视野阈值。

文件位置
--------
把ZIP中的两个文件解压到：

C-CODE\U-UDP002\04_TEMP

- u002_u22b16_loss_transition_timing_assessment_v0_1.py.txt
- u002_u22b16_loss_transition_timing_assessment_algorithm_card_v0_1.json

从C-CODE目录打开CMD。

CMD执行——三行
---------------
python U-UDP002\04_TEMP\u002_u22b16_loss_transition_timing_assessment_v0_1.py.txt --prepare

python U-UDP002\04_TEMP\u002_u22b16_loss_transition_timing_assessment_v0_1.py.txt --self-test

python U-UDP002\04_TEMP\u002_u22b16_loss_transition_timing_assessment_v0_1.py.txt --execute

成功标准
--------
Self-test：

U22B16-SELFTEST-PASS-22-C0

正式执行结果使用新格式，例如：

B16_N16-R15-O14-C1-U0_MED-MX68-RD1-CD10_X0-C0

只需回传这一行。

Capsule解释
-----------
- N：Candidate总数
- R：观察到Radar恢复的Candidate数
- O：无效期间进入外侧比较组的Candidate数
- C：正前方短时丢失对照数
- U：缺少关键证据数
- MX：各Candidate无效期间最大绝对方位角中位数，单位0.1°
- RD：最后一个无效Frame到Radar恢复的中位Frame数
- CD：目标回到中心组后到Radar恢复的中位Frame数
