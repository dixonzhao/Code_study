UDP002 U22B19C Golden Run 恢复验收指南（中文）
版本：v0.5
日期：2026-08-26

一、目的

B19C 使用 B19B 已通过真实数据验证的 S1 v0.4 和 Width Binding Profile，验收已经完成执行的正式 Golden Run。

本步骤不改变任何分析参数，不新增算法，不修改原 Golden Run。唯一受控变化为：

- CameraTargetContinuityArbitration：v0.3.0 -> v0.4.0；
- Binding Profile：切换为 B19B 生成并绑定 SHA-256 的 Width Profile。

新 S1 输出必须与 B19B 已验证的 v0.4 重放文件 SHA-256 完全一致，并且必须完整覆盖本次 resolved ModulePlan 与 U003 Review Package。

重要：S0-S7是固定Stage槽位，不表示每次Run必须在八个槽位都安装Module。当前Radar-loss Golden Run正式选择的是S0、S1、S6、S7；S2-S5没有选择Module，因此4个实际Stage是正确结果。v0.5按resolved ModulePlan逐个核对Module Artifact，不再硬编码要求8个实际Stage。

四、输出规则

prepare 会显示多行人工可读检查结果，包括：

- Workspace；
- B19B Summary；
- 原 Golden Run；
- Width Profile；
- S1 v0.4 Module及资格凭据；
- 正式Run Contract Validator及完整目标配置验证；
- Engine Preflight；
- Stage Executor；
- 新配置和新输出是否保持未占用；
- 07_OUTPUT是否通过创建、写入、读取、文件改名、目录改名和删除共7项权限测试；
- 唯一允许的版本差异；
- TEMP清理结果。

prepare 最后一行应为：

B19CP-M...-R...-P7-E1-A...-L...-X0-C0

如果是 C-0，不需要回传 prepare 的多行信息。

self-test 仍只输出机器码；C-0不需要回传。

execute 会优先识别v0.4已经成功完成的V03 Run，并直接进行恢复验收，不会重复运行Module。正常情况下应在较短时间内完成。

v0.2修正说明：v0.1错误地把Run Configuration文件直接传给Stage Executor。正式契约要求先由Engine Preflight创建PREPARED Run Root，再把该Run Root传给Stage Executor。v0.2已按此固定顺序执行，并在本地使用严格区分“配置文件”和“Run目录”的测试替身完成回归验证。

v0.3修正说明：v0.2使用了Schema不允许的RunPurpose。v0.3将新Run定义为合法且语义一致的EVALUATION，并在Prepare开始前使用公司环境中实际安装的Contract Validator校验完整目标配置。v0.1/v0.2留下的旧配置不会被覆盖；v0.3使用新的V02 Run Id保留审计历史。

v0.4修正说明：v0.3在公司环境进入Engine Preflight时返回了信息不足的PermissionError。v0.4不修改任何分析算法，新增完整输出目录权限测试，并在旧Engine CLI丢失异常位置时，使用同一已安装Engine的公开函数按阶段重放Preflight。若CLI只是边界性失败而同一正式逻辑可完成，运行会记录F1并继续；若确有权限或文件问题，失败码会同时给出阶段、文件、errno、Windows error、代码行和函数。v0.4使用新的V03 Run Id，不覆盖V02残留。

v0.5修正说明：v0.4成功执行了正式ModulePlan，但最终验收错误地要求八个Stage全部产生Artifact。v0.5改为逐个核对resolved ModulePlan中的Module身份、版本和Stage，空Stage槽位不再误判为丢失。v0.5直接恢复验收已完成的V03 Run，不重复进行耗时分析。

五、只回传 execute 最后一行

成功格式：

B19C_N<Rows>-M<Modules>-A<Artifacts>-S<SelectedStages>-T8-W<WidthValid>-F<Fallback>-R<Recovery>-U1-D1-X0-C0

字段：

- N：S1 v0.4输出行数；
- M：固定Pipeline中的Module数量；
- A：新Run的Artifact数量；
- S：本次ModulePlan实际选择并完成的Stage数量；当前正式Run预期为4；
- T：U002固定Stage taxonomy数量，固定为8；
- W：有效Selected Width行数；
- F：Engine Preflight CLI是否触发同逻辑的进程内诊断回退；正常为0，旧CLI边界PermissionError但正式逻辑通过时为1；
- R：是否恢复验收已经完成的V03 Run；本次正常预期为1；
- U：S7/U003 Review Package存在；
- D：新S1表与B19B验证重放SHA-256完全一致；
- X：阻塞问题数；
- C：总状态。

失败格式：

B19CE-K<Reason>-D<Detail>-X1-C7

权限类失败示例：

B19CE-KPERMISSION-DP<Phase>-F<File>-E<Errno>-W<WinError>-L<Line>-N<Function>-X1-C7

失败时只需原样回传最后一行，不要自行修改程序。
