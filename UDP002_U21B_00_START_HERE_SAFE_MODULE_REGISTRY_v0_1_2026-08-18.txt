1. PURPOSE OF THIS TASK

U21A created and accepted the shared U002 Engine lifecycle. U21B now creates
the first safe external Module Registry.

The Registry answers only these questions:

1. Which module_manifest.json files exist under a selected modules directory?
2. Does each Manifest satisfy the frozen U2-0A Module Manifest contract?
3. Are its declared files present and byte-identical to their declared hashes?
4. Is its Engine compatibility range valid for the current Engine version?
5. Is the Module statically eligible for a later controlled self-test?

U21B does not execute Camera, Radar, Baseline, Evidence, Candidate, SysID or
Export algorithms. It does not create a GUI. It does not activate Modules.


2. ENGINEERING REASON

Future U002 capability will be delivered as replaceable Module Packs. The
Engine must not discover Modules by importing every Python file. A broken or
malicious Module must not crash Workbench startup merely because its directory
exists.

Therefore U21B performs data-only discovery first:

modules directory
  -> locate module_manifest.json
  -> validate frozen contract
  -> verify paths, hashes and compatibility
  -> classify status
  -> write deterministic registry_snapshot.json

The implementation file is treated as an inert byte object in U21B. Its hash
may be read, but its code must not be imported, evaluated or executed.

5. IMPLEMENTATION CONSTRAINTS

The program must:

- use Python standard library only;
- work from Windows CMD;
- support paths containing spaces;
- use pathlib for filesystem paths;
- use UTF-8 JSON;
- sort all output deterministically;
- write output atomically using temporary file plus os.replace;
- never modify the scanned Module Pack directories;
- never copy raw source data rows into output;
- never use importlib, __import__, eval or exec on Module code;
- never invoke a Module Entrypoint or its declared SelfTest;
- never use shell=True;
- never silently convert an invalid Module to AVAILABLE;
- never let one invalid Module abort discovery of other Modules.

The trusted frozen contract validator may be called only as this bounded child
process pattern:

  [sys.executable, contract_validator,
   "--schema-bundle", schema_bundle,
   "--validate", module_manifest]

Use shell=False, captured stdout/stderr and a finite timeout. No other Python
file may be executed by U21B.


6. REQUIRED REUSABLE API

Implement functions with these responsibilities. Exact internal class design
is flexible, but the public function names and behavior are required.

  scan_modules(
      modules_root,
      engine_version,
      contract_validator,
      schema_bundle,
  ) -> dict

Returns an in-memory Registry Snapshot. It must not write files.

  write_registry_snapshot(snapshot, output_path) -> None

Writes canonical UTF-8 JSON atomically.

  validate_engine_version(version_text) -> tuple[int, int, int]

Accepts only MAJOR.MINOR.PATCH non-negative integer format.

  sha256_file(path) -> str

Returns the lowercase SHA-256 of exact file bytes.

  main(argv=None) -> int

Implements the CLI and returns a controlled process exit code.


7. DISCOVERY RULE

The selected modules_root must exist and be a directory.

Recursively locate files whose exact filename is:

  module_manifest.json

Each Manifest parent directory is one Module Pack root.

Directories without module_manifest.json are not Modules and are not imported.
They may be counted as unmanaged entries, but must not cause a scan failure.

Do not follow a symlink or junction outside modules_root. If a Manifest, its
Entrypoint or its ConfigurationSchema resolves outside its Module Pack root,
classify that Module as QUARANTINED.

Store only paths relative to modules_root in the Registry Snapshot. Do not store
machine-specific absolute paths in the normal output.


8. REQUIRED STATUS ENUMERATION

The Registry must support these exact statuses:

  AVAILABLE
  INCOMPATIBLE
  INVALID_MANIFEST
  DEPENDENCY_MISSING
  SELFTEST_REQUIRED
  QUARANTINED

U21B is static discovery only. Therefore a statically valid new external Module
normally ends as SELFTEST_REQUIRED, not AVAILABLE.

AVAILABLE is reserved for the later controlled self-test/activation node. U21B
must include AVAILABLE in its known status enumeration but must not invent an
AVAILABLE result without accepted identity-bound self-test evidence.


9. CLASSIFICATION PRECEDENCE

Apply the following precedence from strongest to weakest:

9.1 QUARANTINED

Use QUARANTINED for security or identity-integrity failures, including:

- Manifest, Entrypoint or ConfigurationSchema escapes Module Pack root;
- forbidden symlink/junction behavior;
- observed Entrypoint SHA-256 differs from ImplementationSha256;
- observed ConfigurationSchema SHA-256 differs from declared Sha256;
- two Module Packs declare the same ModuleId plus ModuleVersion identity;
- resolved identity is otherwise ambiguous.

Duplicate identities must quarantine every conflicting entry. Do not choose the
first or latest copy.

9.2 INVALID_MANIFEST

Use INVALID_MANIFEST when:

- JSON cannot be parsed as one object;
- frozen contract validator rejects it;
- required fields are absent or types/enums are invalid;
- relative path syntax is invalid before file lookup.

Record bounded validator stdout/stderr and a stable ReasonCode. Do not store an
unbounded stack trace in Registry Snapshot.

9.3 INCOMPATIBLE

Use INCOMPATIBLE when the current Engine version is below
Compatibility.MinimumEngineVersion or above non-null MaximumEngineVersion.

Use numeric semantic comparison. Never compare version strings lexically.

9.4 DEPENDENCY_MISSING

Use DEPENDENCY_MISSING when a contract-valid compatible Manifest refers to a
missing required local support file, including:

- Entrypoint.RelativeFile does not exist as a regular file;
- ConfigurationSchema.RelativePath does not exist as a regular file.

U21B does not infer third-party package dependencies because ContractVersion
0.1 does not declare such a field. Do not modify the frozen Manifest contract
to add one during this task.

9.5 SELFTEST_REQUIRED

Use SELFTEST_REQUIRED when all static checks pass. This means the Module is
eligible for later isolated self-test, not approved for execution.


10. FILE AND HASH CHECKS

For a contract-valid Manifest:

1. Resolve Entrypoint.RelativeFile from the Module Pack root.
2. Confirm it remains inside the Module Pack root.
3. Confirm it is a regular non-symlink file.
4. Compute exact byte SHA-256.
5. Compare it with ImplementationSha256.
6. Resolve ConfigurationSchema.RelativePath from Module Pack root.
7. Confirm it remains inside the Module Pack root.
8. Confirm it is a regular non-symlink file.
9. Compute exact byte SHA-256.
10. Compare it with ConfigurationSchema.Sha256.

Hash mismatch is QUARANTINED. File absence is DEPENDENCY_MISSING.

U21B must read SelfTest.Arguments, ExpectedExitCode and ExpectedToken only as
Manifest data. It must not run them.


11. REQUIRED REGISTRY SNAPSHOT

The returned/written dictionary must have these top-level fields:

  RegistrySnapshotType
  RegistrySnapshotVersion
  GeneratedAtUtc
  EngineVersion
  ModulesRootIdentity
  ScanPolicy
  StatusCounts
  ModuleCount
  Modules
  UnmanagedEntryCount
  Warnings

Required fixed values:

  RegistrySnapshotType = U002_MODULE_REGISTRY_SNAPSHOT
  RegistrySnapshotVersion = 0.1
  ScanPolicy = STATIC_MANIFEST_ONLY_NO_MODULE_EXECUTION

ModulesRootIdentity must be a safe local identity string derived from the
selected directory name and scan policy. It must not contain raw data rows.

Each Modules entry must contain at least:

  ModuleId
  ModuleVersion
  DisplayName
  Stage
  ModuleKind
  AlgorithmStatus
  ExecutionRequirement
  ManifestRelativePath
  ManifestSha256
  EntrypointRelativePath
  ImplementationSha256Declared
  ImplementationSha256Observed
  ConfigurationSchemaRelativePath
  ConfigurationSchemaSha256Declared
  ConfigurationSchemaSha256Observed
  MinimumEngineVersion
  MaximumEngineVersion
  RegistryStatus
  ReasonCodes
  ValidatorExitCode

For an unreadable or invalid Manifest, fields not safely known must be null.

ReasonCodes must be stable uppercase identifiers, for example:

  MANIFEST_JSON_INVALID
  CONTRACT_VALIDATION_FAILED
  ENGINE_VERSION_OUT_OF_RANGE
  ENTRYPOINT_MISSING
  CONFIG_SCHEMA_MISSING
  IMPLEMENTATION_HASH_MISMATCH
  CONFIG_SCHEMA_HASH_MISMATCH
  PATH_ESCAPE
  FORBIDDEN_SYMLINK
  DUPLICATE_MODULE_IDENTITY
  SELFTEST_NOT_YET_ACCEPTED

Sort Modules by:

  Stage, ModuleId, ModuleVersion, ManifestRelativePath

Sort ReasonCodes and Warnings. StatusCounts must contain all six statuses even
when a count is zero.


12. CLI

Required modes:

12.1 Self-test

  --self-test
  --schema-bundle PATH
  --contract-validator PATH
  --fixture-manifest PATH

12.2 Static scan

  --scan
  --modules-root PATH
  --engine-version MAJOR.MINOR.PATCH
  --schema-bundle PATH
  --contract-validator PATH
  --out PATH

Exactly one of --self-test or --scan is required.

Controlled exits:

  0 = requested operation completed and output is structurally valid;
  7 = controlled validation or execution failure.

On failure print one short line ending in C-7 and write no partial output file.


13. SELF-TEST DESIGN

The self-test must use tempfile.TemporaryDirectory and the accepted
valid_module_manifest.json fixture as its base Manifest. It must not modify the
accepted fixture itself.

Create temporary inert Entrypoint and ConfigurationSchema files, update their
declared hashes, and create synthetic Module Packs covering at least:

1. valid static Module -> SELFTEST_REQUIRED;
2. invalid JSON -> INVALID_MANIFEST;
3. frozen contract violation -> INVALID_MANIFEST;
4. incompatible Engine version -> INCOMPATIBLE;
5. missing Entrypoint -> DEPENDENCY_MISSING;
6. missing ConfigurationSchema -> DEPENDENCY_MISSING;
7. Entrypoint hash mismatch -> QUARANTINED;
8. ConfigurationSchema hash mismatch -> QUARANTINED;
9. duplicate ModuleId plus ModuleVersion -> both QUARANTINED;
10. deterministic Module ordering and StatusCounts;
11. atomic snapshot write/read;
12. absent modules_root controlled failure;
13. no partial output after controlled failure.

The inert Entrypoint should contain code that would create a marker file if it
were executed. After the scan, assert that the marker does not exist. This is
the proof that U21B inspected bytes without executing Module code.

The self-test must perform exactly 24 named checks and print only this success
capsule after all checks pass:

  U21B1 N-T24-V1-I2-C1-M2-Q4-S1-X0 C-0

The count meanings are:

  T24 = 24 named self-test checks passed;
  V1  = one statically valid SELFTEST_REQUIRED fixture;
  I2  = two invalid-manifest fixtures;
  C1  = one incompatible fixture;
  M2  = two missing-dependency fixtures;
  Q4  = four quarantined entries, including both duplicate identities;
  S1  = snapshot write/read and deterministic structure passed;
  X0  = no uncontrolled exception.

On failure print:

  U21B1-ERROR-<STABLE_REASON> C-7
