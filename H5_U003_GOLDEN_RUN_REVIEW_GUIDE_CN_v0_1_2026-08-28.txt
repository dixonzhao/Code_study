H5 Golden Run -> U003 人工复核运行指南 v0.1
日期：2026-08-28
适用环境：Windows CMD；当前目录 C-CODE


一、本次任务是什么
==================

U001 -> U002 S0/S1/S6/S7 已经成功运行，返回：

H5GR-M5-A5-C16-R1954-P3-U1-X0-C0

这表示：
- 5 个正式 Module 已执行；
- 5 类正式 Artifact 已生成；
- 生成 16 个候选区间；
- 生成 1,954 行供 U003 同步显示的 Review Data；
- 自动链已经通过，下一步只做 U003 人工证据复核。


二、找到本次成功 Run
====================

1. 打开：

C-CODE\U-UDP002\07_OUTPUT

2. 按“修改日期”排序，打开最新的 H5 Run 文件夹。

3. 用下面两项确认没有选到旧 Run：

- run_status.json 中 Status = SUCCEEDED；
- 02_DIAGNOSTICS\H5_FULL_CHAIN_CONTROLLER\H5GR_RETURN_CAPSULE.txt 内容为：
  H5GR-M5-A5-C16-R1954-P3-U1-X0-C0

只要这两项不同时满足，就不要拿该文件夹做本轮复核。


三、找到 U003 输入文件
=====================

从上述成功 Run 继续进入：

03_ARTIFACTS\S7
  \<唯一的 CameraRadar.S7.CandidateReviewBatchExport Artifact 文件夹>
    \batches\RB001

RB001 中需要两个文件：

1. event_queue.csv
   - 应有 16 条 Event；
   - 保存 EventID、复核起点、Peak、终点、优先级、原因和 Review Memo。

2. review_data.csv
   - 应有 1,954 行数据；
   - 用于 U003 右侧 CAN 表、黄色当前行和候选区间联动。

不要把 complete_candidate_inventory.csv 当作 Event Queue，也不要加载旧 Run 的 CSV。


四、启动当前 U003
=================

在 C-CODE 目录的 CMD 只运行这一行：

python U-UDP003\01_PROGRAMS\u003_evidence_review_workbench_v0_21.py

启动后选择 EN 或 JA。本次语言只影响界面；开始复核后不要中途切换语言。

说明：当前应使用高代码 U003 v0.21 源码。不要启动旧的 v0.13 one-file EXE，
因为旧 EXE 不包含后续加入的 Module、Review Memo 和界面修补。


五、按顺序装入材料
==================

1. 点击 Open Video，选择本次 Stereo Camera 视频。

2. 点击 Load Event CSV，选择本次 RB001\event_queue.csv。

3. 点击 Load Signal CSV（或 CAN 窗口中的 Load Review Data CSV），选择：
   RB001\review_data.csv。

4. 点击 Show CAN Window，确认右侧同步表出现数据。


六、设置 FrameCount 映射
========================

本视频与 CAN 的规则不是强制 1:1。已知本次通常为：

- 视频约 10 fps；
- CAN FrameCount 约 20 Hz；
- 因此优先使用 Rate-based。

填写：

- Video anchor index：0
- CAN anchor FC：视频第 0 帧左下角显示的 FrameCount
- CAN rate (Hz)：20
- Mode：Rate-based

点击 Apply Mapping。

成功时说明文字应接近：

1 video frame = 2 CAN counts

如果视频第 0 帧看不到 FrameCount，就选择一个能清楚读取 FrameCount 的视频帧，并把：

- 该视频帧序号填入 Video anchor index；
- 画面上显示的数值填入 CAN anchor FC。


七、先做 5—10 分钟结构验收
============================

在正式看完 16 个 Event 前，先确认以下六项：

1. Event 列表显示 16 个候选；
2. Review Data 显示 1,954 行；
3. Previous / Next 可以切换 Event；
4. Jump / Pin Peak 能跳到候选 Peak；
5. 视频位置变化时，CAN 表黄色行同步变化；
6. 当前 Event 的自动 Review Memo 可以显示。

结构验收成功后只回传：

H5U3-L1-E16-D1954-V1-S1-J1-M1-X0-C0

字段含义：
- L1：两份 CSV 均已加载；
- E16：16 个 Event；
- D1954：1,954 行 Review Data；
- V1：视频正常；
- S1：视频与 CAN 同步移动；
- J1：Peak 跳转正常；
- M1：Review Memo 正常显示。

如失败，只回传：

H5U3E-K<简短错误关键词>-X1-C7

并补 1 条短 Memo，说明在哪一步失败。


八、正式复核 16 个 Event
=======================

逐个 Event 执行：

1. 跳到 Event Start，观察候选前状态；
2. 播放到 Peak，并核对黄色 CAN 行；
3. 播放到 Event End，观察 Radar 是否恢复；
4. 比较视频目标、Camera 数据、RadarMeasurementValid、候选理由和 Review Memo；
5. 选择 Result code；
6. 必要时修改 Review Memo；
7. 点击 Save Event Review；
8. 切换到下一个 Event。

Result code：

- 1 = 候选成立，视频/CAN证据符合预期；
- 2 = 候选不成立或信号对应错误；
- 3 = 真实目标或场景变化，不应按同类异常解释；
- 4 = 无法判断、同步/信号定义/证据不足；
- 5 = 视频不可用。

注意：Result code 1 表示“这个候选识别正确”，不代表已经证明 Radar 的硬件根因。
本轮正式结论仍是 Radar measurement-loss candidate，经视频和 CAN 证据确认。


九、保存复核结果
================

16 个 Event 全部完成后：

1. 点击 Export Reviews；
2. 输出到本次成功 Run 外的独立人工复核文件夹，避免修改 S7 原始 Artifact；
3. 确认导出文件存在且含 16 个 Event；
4. 原始 event_queue.csv 和 review_data.csv 保持只读，不要覆盖。

正式复核完成后的简短回传格式：

H5VR-N16-R16-C1<数量>-C2<数量>-C3<数量>-C4<数量>-C5<数量>-X0-C0

Memo 只补 1—3 条无法用代码表达的重要异常。


十、当前成功标准
================

本节点结束条件不是“所有候选都必须正确”，而是：

- U001 可信源表能够进入 U002；
- U002 能执行 S0 -> S1 Camera -> S1 Radar -> S6 -> S7；
- S7 能输出完整候选及 U003 Review Data；
- U003 能加载视频、Event Queue 和 Review Data；
- 工程师能够完成同步复核、修改 Memo 并导出结果。

以上全部成立，即完成第一条可复核 Golden Run 闭环。
