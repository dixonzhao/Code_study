5. CONTROL-FLOW AUDIT

Across the complete source, identify:

- compound statements whose suite contains several semicolon-separated simple
  statements on the header's physical line;
- any Raise, Return, Break or Continue before later statements in that same
  suite;
- later statements therefore unreachable on the taken branch;
- counter/list updates incorrectly inside a failure-only conditional suite;
- all occurrences structurally equivalent to the confirmed ck(v) defect;
- total physical lines containing semicolon-separated executable statements;
- nested definitions or self-test bodies compressed onto very few physical
  lines such that traceback localization becomes ambiguous.

Confirm the ck(v) defect structurally, not by matching source text.


6. RUNTIME-BUDGET AUDIT

Build a static call graph rooted at `selftest` with cycle protection. Across all
reachable functions identify:

- subprocess.run/Popen/check_call/check_output/communicate/wait call sites;
- timeout keyword/argument values resolved from literals or simple assignments;
- time.sleep call sites and resolved values;
- child command modes (`--self-test`, `--module-worker`,
  `--dependency-preflight`, other);
- literal loop/list/range multiplicities around timed calls;
- repeated calls from selftest to the same timed helper;
- possible recursion into complete selftest;
- unresolved dynamic timeout or multiplicity sites.

Compute a conservative static budget only for resolved timed calls:

  resolved_budget_seconds = sum(timeout_or_sleep * resolved_multiplicity)

This is not measured runtime. If a multiplicity is unresolved, count it in U
and do not fabricate a total contribution.
