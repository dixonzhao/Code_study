COMPLETE IMPLEMENTATION SPECIFICATION v0.2

======================================================================
1. PROGRAM IDENTITY AND SAFETY
======================================================================

Filename:

u001_auto_discovery_profile_builder_v0_2.py

Purpose:

Convert one accepted Gate 1 signal catalog into a complete, deterministic,
traceable, provisional AUTO_DISCOVERY configuration set.  All source-present,
DBC-matched, technically decodable signals are included as discovery
candidates except the single authoritative FrameCount key.

Import safety:

- importing the module performs no file I/O, GUI work, computation or logging;
- CLI execution occurs only below `if __name__ == "__main__":`;
- input files are read-only;
- output is written only under the explicit --out folder;
- no global pandas options are modified;
- no absolute company path is stored in an output artifact.

Allowed dependencies:

- Python standard library;
- pandas.

======================================================================
2. CLI
======================================================================

Self-test:

python u001_auto_discovery_profile_builder_v0_2.py --self-test

Build:

python u001_auto_discovery_profile_builder_v0_2.py --build ^
  --catalog "PATH_TO_udp001_g1_signal_catalog.csv" ^
  --out "PATH_TO_AUTO_DISCOVERY_ALL_V0_2" ^
  --profile-id "AUTO_DISCOVERY_ALL_V0_2" ^
  --frame-key-channel 2 ^
  --frame-key-can-id 0x620 ^
  --frame-key-signal FrameCount ^
  --batch-size 32

Validate a completed output independently from the build step:

python u001_auto_discovery_profile_builder_v0_2.py --validate-output ^
  --out "PATH_TO_AUTO_DISCOVERY_ALL_V0_2"

Optional build flag:

--overwrite

Rules:

- default batch size is 32;
- batch size must be an integer from 8 through 64;
- without --overwrite, refuse to write into an existing nonempty output folder;
- --validate-output never edits an artifact;
- invalid CLI combinations fail with a nonzero process exit code.

======================================================================
3. GATE 1 INPUT CONTRACT
======================================================================

Required logical columns, with surrounding whitespace ignored and header case
matched case-insensitively:

- Channel
- CAN_ID_Hex
- MessageName
- SignalName
- Unit
- SourceGroupComplete
- ReuseStatus
- ProposedValueKind
- ProposedSignalRole
- ProposedUpdateMode
- InferenceWarning

No other aliasing is permitted.  If two physical headers normalize to the same
logical field, stop as ambiguous.  If a required field is missing, stop.  Do
not manufacture a blank required field.

Catalog row count C means the number of parsed logical data rows, excluding the
header and ignored fully blank lines, before eligibility filtering.

Normalize text for comparisons by trimming surrounding whitespace.  Preserve
the original logical values in the inventory where possible.

SourceGroupComplete is true only for normalized values `1` or `true`
(case-insensitive).  Any other value is not complete.

ReuseStatus is matched only when the trimmed value equals `MATCHED`
(case-insensitive).

Channel must parse as a positive integer without a fractional part.

CAN_ID_Hex must parse as a nonnegative CAN identifier.  Accept `0x`-prefixed
hexadecimal text and canonical hexadecimal text emitted by Gate 1.  Store the
normalized output as uppercase `0x` plus uppercase hexadecimal digits.

======================================================================
4. CANONICAL NAME
======================================================================

For rows with parseable Channel, CAN ID and nonblank SignalName, generate:

CH{Channel}_{CAN_ID_without_0x}_{SignalName}

Sanitize every non-ASCII-letter, non-ASCII-digit and non-underscore character
to one underscore.  Collapse repeated underscores and strip leading/trailing
underscores.  The result must be nonblank.

CanonicalName is the stable machine identity.  Among otherwise eligible rows,
any duplicate CanonicalName is blocking.  List the colliding source identities
and exit nonzero.  Do not silently append `_2` or another suffix.

======================================================================
5. TECHNICAL ELIGIBILITY AND COMPLETE PARTITION
======================================================================

Every catalog row must enter exactly one partition: ELIGIBLE or EXCLUDED.

A row is ELIGIBLE only when all conditions are true:

- ReuseStatus = MATCHED;
- SourceGroupComplete is true;
- Channel is a valid positive integer;
- CAN_ID_Hex is parseable;
- SignalName is nonblank;
- CanonicalName is valid and unique.

Do not exclude by signal name because it looks like a counter, identifier,
flag, reserved value, unknown business term or high-rate signal.

For an excluded row, Selected=0 and ExclusionReason contains one or more of
these deterministic semicolon-separated codes in the order shown:

1. REUSE_STATUS_NOT_MATCHED
2. SOURCE_GROUP_INCOMPLETE
3. INVALID_CHANNEL
4. INVALID_CAN_ID
5. BLANK_SIGNAL_NAME
6. INVALID_CANONICAL_NAME

CanonicalName collisions among otherwise eligible rows are blocking rather
than an exclusion category.

The configured FrameCount identity is the exact normalized triple:

- Channel = 2;
- CAN_ID_Hex = 0x620;
- SignalName = FrameCount.

It must exist among eligible rows exactly once.  It is the only Required=1
row.  All other eligible rows are Selected=1 and Required=0.

FrameCount is not a discovery candidate and is never placed in a batch.

======================================================================
6. COUNT DEFINITIONS AND BLOCKING INVARIANTS
======================================================================

Use these meanings everywhere in inventory, manifest, validation and capsule:

- C = catalog_row_count before filtering;
- E = eligible_signal_count including the one FrameCount row;
- X = excluded_signal_count;
- K = frame_key_count;
- V = candidate_signal_count excluding FrameCount;
- B = batch_count;
- F = fallback_total_count;
- H = hash_failure_count.

Required success invariants:

1. C = E + X
2. C >= 1
3. E >= 2
4. K = 1
5. V = E - K
6. B = ceil(V / batch_size)
7. every eligible row is present once in each applicable control table
8. every candidate is present exactly once in the batch map
9. FrameCount is present zero times in the batch map
10. H = 0

Implement one explicit `validate_count_invariants` function.  Call it before
writing a successful manifest/capsule and again from --validate-output after
recomputing counts from physical output files.

Any invariant failure produces nonzero process exit and C-7.  It must never
produce a success claim.

Do not hard-code real-data counts.  The previously observed inconsistent
pattern C705/E706/X406/V706 must be rejected by a regression test.  A coherent
example C1112/E706/X406/K1/V705/B23 must pass for batch size 32.

======================================================================
7. PROVISIONAL SEMANTIC CLASSIFICATION
======================================================================

Accepted ValueKind vocabulary:

- FLOAT
- INTEGER
- BOOLEAN
- ENUM
- BITFIELD

Accepted SignalRole vocabulary:

- MEASUREMENT
- STATE
- EVENT_FLAG
- VALIDITY_FLAG
- COUNTER
- IDENTIFIER
- FRAME_KEY

Accepted UpdateMode vocabulary:

- PERIODIC
- ON_CHANGE
- EVENT
- UNKNOWN

Use the Gate 1 ProposedValueKind, ProposedSignalRole and ProposedUpdateMode when
their normalized values are accepted.

Fallbacks:

- invalid/blank ProposedValueKind -> FLOAT;
- invalid/blank ProposedSignalRole -> MEASUREMENT;
- invalid/blank ProposedUpdateMode -> UNKNOWN.

Record each fallback in InferenceWarning and Notes.  Count the three fallback
types separately and set F to their sum.  One row may contribute up to three
fallbacks.

StorageDtype:

- FLOAT -> Float64
- INTEGER -> Int64
- BOOLEAN -> boolean
- ENUM -> Int64
- BITFIELD -> Int64

FrameCount overrides all proposals:

- ValueKind = INTEGER
- SignalRole = FRAME_KEY
- UpdateMode = PERIODIC
- StorageDtype = Int64
- Required = 1

Every G4 discovery row uses:

- ValidityRule = NONE
- InvalidExactValues blank
- DBCMinimum blank
- DBCMaximum blank
- UserMinimum blank
- UserMaximum blank
- InvalidReasonCode blank
- ValiditySourceSignal blank
- ValidityExpression blank

Do not guess invalid defaults such as 327.66, zero, 273.15 or any
signal-specific sentinel.

Every Notes field begins with `AUTO_DISCOVERY_PROVISIONAL` and appends source
InferenceWarning/fallback information when present.

======================================================================
9. DETERMINISTIC ORDER AND BATCH MAP
======================================================================

Stable eligible/candidate order:

1. Channel numeric ascending;
2. CAN ID numeric ascending;
3. MessageName Unicode ordinal ascending;
4. SignalName Unicode ordinal ascending;
5. CanonicalName Unicode ordinal ascending;
6. original CatalogRowOrdinal ascending as final tie-breaker.

FrameCount is removed only after eligible ordering and is not assigned a
candidate ordinal.

Split candidates into consecutive batches of --batch-size.

- BatchId = B001, B002, ... with no gap;
- BatchOrdinal starts at 1;
- SignalOrdinalGlobal starts at 1 and has no gap;
- SignalOrdinalInBatch starts at 1 in every batch;
- no batch exceeds batch_size;
- same catalog/profile/frame identity/batch size yields byte-repeatable maps.

Exact u001_discovery_batch_map.csv columns:

1. ProfileId
2. BatchId
3. BatchOrdinal
4. SignalOrdinalGlobal

6. CanonicalName
7. Channel

9. MessageName

11. Unit

PolicyStatus = AUTO_DISCOVERY_PROVISIONAL for every row.

======================================================================
14. READ-ONLY OUTPUT VALIDATION
======================================================================

--validate-output must independently read the completed folder and check:

- exactly the eight required filenames are present;
- exact CSV schemas and order;
- inventory partition and C=E+X;
- one exact FrameCount key;
- control-table membership/count consistency;
- G4 ValidityRule=NONE;
- G5 policy rules;
- G6 candidate-only membership and HoldPolicy=NONE;
- candidate-to-batch one-to-one mapping;
- sequential SignalIndex/BatchId/ordinals;
- batch width <= batch_size;
- manifest identity/counts equal recomputed values;
- all six manifest CSV hashes, rows and columns match;
- capsule values equal recomputed values;
- no absolute path occurs in manifest.

Required success final line:

UDP001-G10A2-VALIDATE-PASS C{C}-E{E}-X{X}-K1-V{V}-B{B}-F{F}-H0

Validation failure exits nonzero and names the failed invariant.  It never
repairs or rewrites output.

======================================================================
15. U001-U002 MACHINE HANDOFF PREPARATION
======================================================================

G10A machine-facing artifacts are:

- u001_discovery_signal_inventory.csv;
- u001_discovery_batch_map.csv;
- u001_discovery_profile_manifest.json.

Interface guarantees:

- ProfileId and CanonicalName are stable identities;
- BatchId is deterministic for identical inputs/configuration;
- every candidate maps to exactly one batch;
- every exclusion is explicit;
- paths are package-relative;
- hashes/counts let U002 reject stale or mixed artifacts;
- C-0 means configuration-contract completeness, not statistical relevance;
- G10A never invokes U002 or writes U002 results.

G10B will create bounded-width data shards following this batch map.  U002 will
consume shards sequentially or with bounded parallelism, join outcomes by
FrameCount, preserve validity/updated/age provenance and never replace missing
values with zero.

======================================================================
16. NON-GOALS AND FORBIDDEN CHANGES
======================================================================

G10A2 must not:

- decode Raw CAN rows;
- create a single 700-column human-review table;
- calculate correlation, NMI, lag, gain, baseline, residual or anomaly score;
- infer reference/target or ground truth;
- infer invalid sentinels;
- apply any cross-frame hold or zero fill;
- overwrite the six-signal controlled profile;
- modify Gate 1-G9, GUI, orchestrator, portable host or package builder;
- modify source CSV, DBC or accepted Case artifacts;
- start G10B/G10C/U002.
