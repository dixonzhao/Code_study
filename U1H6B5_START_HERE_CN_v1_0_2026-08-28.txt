U001 H6B5：22信号语义策略与高代码H3 Frame域构建
=================================================

本节点做什么
------------
1. 自动将 U1H6B0、B1、B2 的旧 active output 移入 A-Archive；
2. 保留 B3（22信号配置）和 B4（正式H2解码结果）；
3. 为22个信号生成明确的类型、角色和内在失效值策略；
4. 使用 FrameCount 建立 Frame assignment；
5. 输出保持来源、数值、有效性与缺失原因的 H3 Canonical Update Package。

当前正式策略
------------
- FrameCount：FRAME_KEY；
- Distance / Speed / Lateral / Width：MEASUREMENT；
- ObjectType：STATE；
- SwitchingFlag：EVENT_FLAG；
- PrecedingVehicleDetectionFlag：VALIDITY_FLAG；
- MessageCounter：COUNTER；
- Camera Distance = 327.66：无效测量；
- Radar DistanceToObject = 0：无效测量；
- 其他未经确认的默认值不在本节点猜测；
- Frame assignment 最大允许距上一次FrameCount更新200个Source Row。

本节点不做
----------
- 跨Frame forward fill / hold；
- Camera 1/3连续性选择；
- Radar业务有效性组合判断；
- 异常分析。

放置位置
--------
将两个文件直接放入：
C-CODE\U-UDP001\04_TEMP

从 C-CODE 目录依次执行（仅三行）
---------------------------------
python U-UDP001\04_TEMP\u001_h6b5_h3_semantic_frame_compile_v1_0.py.txt --prepare
python U-UDP001\04_TEMP\u001_h6b5_h3_semantic_frame_compile_v1_0.py.txt --self-test
python U-UDP001\04_TEMP\u001_h6b5_h3_semantic_frame_compile_v1_0.py.txt --execute

说明
----
- prepare 会自动归档 B0-B2、旧B5输出及已替代的B4中转文件。
- 不要手动删除 B3 或 B4；它们仍是当前正式依赖。
- self-test 会验证 Frame compiler、Policy compiler、Projector 与 H3 Engine。
- execute 需要多次流式读取 H2 更新长表并计算Hash，CPU占用仍可能较低，但内存保持有界。
- 失败后修正原因，并重新从 prepare 开始。

需要回传
--------
只回传 execute 最后一行：

U1H6B5-R...-F...-S22-V...-I...-U...-E3-X0-C0

字段：
- R：H3输入Update数；
- F：Distinct FrameCount数；
- S：正式信号策略数；
- V / I：H3有效 / 无效Update数；
- U：未能分配Frame的Source Row数；
- E：带明确Exact invalid规则的信号数；
- X0-C0：成功。
