# Hit & Blow 開発計画書・コード説明資料

## 1. 文書の目的

この文書は、Hit & Blowゲームの開発内容とプログラムを説明するための資料です。

説明は、次の二つに分けます。

1. ゲームの処理と実装方法
2. 課題で指定されたコーディングルール

最初にプログラムの動きを説明し、細かい書き方のルールは最後に説明します。

## 2. 開発概要

| 項目 | 内容 |
|---|---|
| プログラム名 | Hit & Blow |
| 使用言語 | C言語 |
| 答え | 0〜9から作る重複しない4桁 |
| 入力 | プレイヤーが入力する4桁の数字 |
| 判定 | HitとBlowを表示 |
| 終了条件 | 4 Hitになったとき |

### HitとBlowの意味

- Hit: 数字と位置が両方同じです。
- Blow: 数字は同じですが、位置が違います。

例えば、正解が`1234`で入力が`1834`の場合、結果は`3 Hit 0 Blow`です。

## 3. 開発方針

プログラムを三つの機能に分けます。

| 機能 | 担当する関数 | 内容 |
|---|---|---|
| ゲーム進行 | `main()` | 入力、入力確認、繰り返し、終了 |
| 答えの作成 | `makeCorrect()` | 重複しない4桁の答えを作る |
| 答えの判定 | `checkCorrect()` | HitとBlowを数え、結果を表示する |

機能を分けることで、一つの関数の仕事が分かりやすくなります。

## 4. ファイル構成

| ファイル | 役割 |
|---|---|
| `hitandblow.c` | `main()`を実装する |
| `hbsetting.c` | `makeCorrect()`を実装する |
| `hbsetting.h` | `makeCorrect()`を宣言する |
| `hbjudge.c` | `checkCorrect()`を実装する |
| `hbjudge.h` | `checkCorrect()`を宣言する |

ソースファイルには処理を書き、ヘッダーファイルには必要な関数の宣言だけを書きます。

## 5. プログラム全体の流れ

```text
ゲーム開始
    ↓
乱数を準備する
    ↓
makeCorrect()で答えを作る
    ↓
4桁の入力を受け取る
    ↓
数字だけか、4桁かを確認する
    ↓
入力エラー ── はい ──→ もう一度入力する
    ↓ いいえ
checkCorrect()で判定する
    ↓
戻り値が0 ──→ もう一度入力する
    ↓
戻り値が1
    ↓
正解メッセージを表示して終了する
```

## 6. プログラムのロジックと実装

### 6.1 `main()`の処理

`main()`はゲーム全体の進行を担当します。

1. `srand()`と`time()`で乱数を準備します。
2. `makeCorrect()`を呼び、正解を受け取ります。
3. ゲーム開始メッセージを表示します。
4. プレイヤーの入力を文字列として受け取ります。
5. 入力が4文字か確認します。
6. すべての文字が数字か確認します。
7. 文字列を`int`に変換します。
8. `checkCorrect()`を呼びます。
9. 戻り値が`0`なら入力を繰り返し、`1`なら終了します。

入力を最初に文字列として読む理由は、`0987`の先頭の`0`と入力した文字数を確認するためです。
判定関数に渡す前に`int`へ変換するため、課題指定の関数インターフェースは変更しません。

### 6.2 `makeCorrect()`の処理

`makeCorrect()`は、同じ数字がない答えを作ります。

1. `rand() % 10`で0〜9の数字を一つ作ります。
2. 前に作った数字と同じか、`for`文で確認します。
3. 同じ数字があれば配列に入れません。
4. 同じではなければ配列に入れます。
5. 配列に4個入るまで繰り返します。
6. 4個の数字を一つの`int`にして返します。

例えば、配列が`{1, 2, 3, 4}`の場合、次の計算で`1234`にします。

```text
0 → 1 → 12 → 123 → 1234
```

### 6.3 `checkCorrect()`の処理

`checkCorrect(int cor, int ans)`は、正解と入力を比較します。

最初に、二つの`int`を4個の数字に分けます。

```text
1234 → {1, 2, 3, 4}
```

判定は二回に分けます。

1. 一回目は、同じ位置の数字を比較してHitを数えます。
2. 二回目は、Hitではない位置を比較してBlowを数えます。

`usedCorrect`と`usedAnswer`は、すでに使った位置を記録する配列です。
この配列があるため、一つの数字を二回数えることがありません。

判定後の処理は次のとおりです。

| 状態 | 表示 | 戻り値 |
|---|---|---:|
| 正解 | `4 Hit 0 Blow`と正解メッセージ | `1` |
| 不正解 | `x Hit x Blow` | `0` |

前のプログラムは`Hit × 10 + Blow`を返していました。
今回は課題の指定に合わせ、ゲームを続けるかどうかを表す`0`または`1`だけを返します。

### 6.4 前の0の特別な処理

課題の例には`0987`があります。
しかし、`int`では`0987`を保存すると`987`になります。

このプログラムでは、入力時に文字列を使って先頭の`0`を確認します。
その後、`checkCorrect()`が右から必ず4回数字を取り出します。
そのため、`987`は判定するときに`{0, 9, 8, 7}`として扱われます。

## 7. 課題指定のコーディングルール

この章はゲームのロジックではなく、コードの書き方についての説明です。

| ルール | 対応した内容 | 理由 |
|---|---|---|
| 関数名 | `checkCorrect`に統一 | lowerCamelCaseに合わせるため |
| ファイル分割 | 機能ごとに`.c`と`.h`を分けた | 各ファイルの役割を明確にするため |
| ヘッダー保護 | `#ifndef`、`#define`、`#endif`を使用 | 同じ宣言の重複を防ぐため |
| ヘッダーの内容 | 必要な関数宣言だけを公開 | 実装をソースファイルに置くため |
| include方法 | 自作ヘッダーを`"..."`で指定 | 自分のファイルであることを示すため |
| グローバル変数 | 使用しない | 関数ごとのデータを分かりやすくするため |
| 数字の桁数 | `DIGIT_COUNT`を使用 | 数字の`4`の意味を明確にするため |
| 変数宣言 | 原則として一行に一つ | 読みやすくするため |
| 制御文 | 必ず大括弧を使用 | 処理の範囲を明確にするため |
| 名前 | lowerCamelCaseの分かりやすい英語 | 変数と関数の意味を伝えるため |
| コメント | `/* ... */`に統一 | コメント形式をそろえるため |
| 最終コード | デバッグ処理や古いコードを残さない | 提出用コードをきれいにするため |

関数名は前のバージョンで`Checkcorrect`と書いていました。
命名規則が正しくなかったため、宣言、定義、呼び出しを`checkCorrect`に修正しました。
