U003 v0.10 + B16时序复核执行指南
================================

本次目的
--------
使用U003复核B16生成的16个Radar无效事件，确认以下时间顺序是否与视频和CAN数据一致：

Camera目标外移 → Radar数据无效 → Camera目标回到中心 → Radar重新恢复。

本次不重新计算候选，也不确定Radar视野阈值。U003只负责最终人工证据确认。


程序放置位置
------------
把下载的：

u003_evidence_review_workbench_v0_10.py.txt

放到现有U003程序目录：

C-CODE\U-UDP003\02_Programs

可以暂时保留v0.9；确认v0.10正常后再将v0.9收入A-Archive。


CMD启动——从C-CODE目录执行
--------------------------
1. 自测：

python U-UDP003\02_Programs\u003_evidence_review_workbench_v0_10.py.txt --self-test

2. 启动GUI：

python U-UDP003\02_Programs\u003_evidence_review_workbench_v0_10.py.txt

自测成功结果：

U003-V010-SELFTEST-PASS-25


GUI中加载的文件
---------------
1. 使用Open Video加载本次Stereo Camera视频。

2. 使用Load Event CSV加载：

C-CODE\U-UDP002\07_OUTPUT\U22B16_LOSS_TRANSITION_TIMING_ASSESSMENT_V01\u003_transition_review\event_queue.csv

3. 在右侧CAN窗口使用Load Review Data CSV加载：

C-CODE\U-UDP002\07_OUTPUT\U22B16_LOSS_TRANSITION_TIMING_ASSESSMENT_V01\u003_transition_review\review_data.csv

4. FrameCount映射继续使用本次已经确认过的视频Anchor和1:1映射。不要重新猜测Offset。


复核顺序
--------
逐个Event使用Event导航。先看Review Memo和Peak，再前后播放确认：

1. Camera显示的目标是否与CAN选中的Camera目标一致；
2. 目标是否在Radar无效前或无效期间明显离开中心；
3. Radar无效是否是真实连续区间；
4. Camera目标回到中心后，Radar是否随后恢复；
5. 是否存在目标切换、遮挡、视频/CAN不一致或其他更合理解释。

重点检查：

- 两个TransitionClass不是OFF_AXIS开头的Event；
- C0010；
- Review Memo中恢复间隔明显较长的Event。


Review Code
-----------
1 = Camera目标、外侧运动、Radar无效及恢复顺序一致

2 = 所选Camera目标或Bearing与视频不一致，不能用于方位角证据

3 = Radar无效真实，但明显属于目标切换、遮挡或其他场景因素

4 = 中心区域短时无效、同步疑问或暂时无法解释

5 = 视频不可用

Review Memo已经由B16提供。只有实际观察与Memo不一致时才修改，避免增加人工负担。


导出与回传
----------
全部16个Event复核后点击Export Reviews。

U003 v0.10会生成：

- 完整Review CSV，保存在公司电脑；
- 一条带时间戳的紧凑Return Capsule。

新格式中：

- 下划线分隔逻辑区块；
- 连字符分隔区块内部字段；
- 同一个Review Code存在不连续区间时，会重复该Code区块。

示例：

RV260825T123456_N16-R16_C1-1-9_C1-11-16_C4-10

下一次只需完整回传这一行。若某个Event必须解释，再补1至3条短Memo。
