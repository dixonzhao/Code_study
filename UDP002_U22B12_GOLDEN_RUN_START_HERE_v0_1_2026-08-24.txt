一、这一步在做什么

U22B11 已经通过机器验收和人工视频复核。本步骤不再调 Camera 选择参数，
而是把已冻结的 Camera S1 Module 0.3.0 接回 Radar S1 与 S2-S7，执行一次
完整的 9-Module 垂直链路：

S0 U001 intake
-> S1 Camera reconstruction 0.3.0
-> S1 Radar validity
-> S2 comparison population
-> S3 signed discrepancy
-> S4 distance-bin median baseline
-> S5 robust residual evidence
-> S6 candidate synthesis
-> S7 U003 review export

执行范围固定为 FrameCount 41380-41780，共 401 帧。

五、只回传什么

成功时只回传一行 B12G：

B12G N-M9-A9-F401-R...-V...-L...-C...-W...-P...-D...-X0 C-0

字段含义：

M = Module 数量
A = Artifact 数量
F = Frame 行数
R = 正式 comparison eligible 行数
V = residual evidence valid 行数
L = Radar target-loss evidence 行数
C = 输出候选数量（允许 0-40）
W = 合并后的 U003 review window 数量
P = 第一优先候选 PeakFrameCount；无候选时为 0
D = 已知设计缺口提示。D1 表示本区间存在 Radar 丢失，但当前 S6 只消费
    valid residual evidence，尚没有独立的 validity-transition candidate 分支。

D1 不是运行失败，也不要因此修改 discrepancy 或把无效 Radar 数值强行纳入计算。

失败时回传两行：

B12GE ... C-7
B12GD ... C-0

不要自行修改旧配置、旧 Run、Core 或 Module。完整错误细节已写入程序输出和
诊断记录；根据两行短码再决定修正路径。

六、成功标准

必须同时满足：

- C-0；
- M9、A9、F401；
- 9 个 Module 的身份与顺序固定；
- Artifact Store 审计通过；
- Candidate 数量不超过 40；
- S7 review package validation 为 PASS；
- ReviewResult / ReviewMemo 保持空白，等待人工填写；
- Radar 不被声明为 ground truth；
- Candidate 不被声明为 confirmed event 或 root cause。

本步骤是 401 帧范围的“纵向贯通验收”，不是全视频性能验收。通过后先查看
实际候选与 U003 输出，再决定是扩展全视频，还是先补独立的 Radar validity
异常候选分支。
