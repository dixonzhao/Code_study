UDP002 U22B1 B14-R4 — G7 v0.5 受控 Schema Completion
日期：2026-08-21

目的
====

修复 B14-R3 暴露的真实接口差异：

    B14R3E K-UPDATE_COLUMN-X1 C-7
    B14R3D D-CLOCKDOMAIN C-0

这不是 G4 业务数据错误。根据已批准的 G8R3 修正规范，G4 Update Stream
允许缺少 ClockDomain、NativeTimestamp、MessageCounter；最终 G7 负责受控补全。

v0.5 只做以下工作：

1. ClockDomain 每行写入 FRAMECOUNT_VIDEO；
2. NativeTimestamp 保持空白，因为当前 CAN timestamp 不可信；
3. MessageCounter 保持空白，不从同名业务信号推测；
4. 按 Data Contract 固定最终 D1 列顺序；
5. 保留所有上游单元格语义、SourceRowIndex 顺序和行数；
6. 不排序、不筛选、不插值、不 forward fill、不补测量值。

需要放在 C-CODE\U-UDP001\04_TEMP 的文件
==============================================

只保留并使用这两个程序文件：

1. u001_output_package_assembler_v0_4.py.txt
2. u001_output_package_assembler_v0_5.py.txt

v0.5 是受控修正层，v0.4 是其经过自测的动态装包引擎，两者必须同目录。
不要再执行旧的 v0.1/v0.2 hotfix。

Step 1 — 自测
===============

在 C-CODE 根目录使用 CMD：

python U-UDP001\04_TEMP\u001_output_package_assembler_v0_5.py.txt --self-test

成功时最后应看到：

UDP001-G7V05-SELFTEST-PASS-56

前面同时出现 v0.4 的 PASS-40 属于依赖引擎自测，正常。

Step 2 — 删除本次失败后产生的不完整 R3 输出
===============================================

请只删除你刚才运行 B14-R3 时新生成、并含有：

u001_g7v04_failure_diagnostic.json

的那个 R3 输出目录。

不要删除原始 B14 失败 Run，也不要修改 U-UDP001\01_PROGRAMS 或 02_CONTROL。

Step 3 — 重新运行 recovery
===========================

使用你执行 B14-R3 时完全相同的四个路径：

- --udp001-root
- --failed-run-root
- --out-root
- 原 Dataset/Run/Segment/Source identity

唯一改变：

程序文件从：

u001_output_package_assembler_v0_4.py.txt

改为：

u001_output_package_assembler_v0_5.py.txt

CMD 模板：

python U-UDP001\04_TEMP\u001_output_package_assembler_v0_5.py.txt --recover-b14 --udp001-root "U-UDP001" --failed-run-root "<原B14失败Run目录>" --out-root "<新的B14R4输出目录>" --dataset-id "<原值>" --run-id "<原值>" --segment-id "<原值>" --source-id "<原值>"

注意：

- out-root 必须是一个尚不存在的新目录；
- 不要复用旧 R3 输出目录；
- failed-run-root 必须仍指向原始 B14 失败 Run；
- v0.5 不调用旧 G7，也不修改已验收 U001。

成功回传
========

只回传新输出目录中的：

u22b1b14r4_return_capsule.txt

内容只有两行，格式如下：

B14R4 N-G7V05-F6-C...-V...-U...-R...-H1-X0 C-0
B14R4S N-M3-C0-N0-G0-X0 C-0

M3 表示输入 G4 缺少三个由 G7 受控补全的 schema 字段；这是预期证据，
不是错误。C/N/G 必须全部为 0。

失败回传
========

若失败，只回传终端最后两行 B14R4E / B14R4D，不需要再运行额外 probe。
