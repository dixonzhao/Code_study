1. CORRECTION SCOPE

Promotion v0.1 correctly failed closed because it required GateStatus,
ReturnCapsule and candidate logical basenames inside the Gate acceptance JSON,
but the accepted Gate specification did not require those JSON fields.

Do not edit, normalize or replace either original Gate evidence file. Promotion
v0.2 treats the following immutable files as one composite evidence set:

  u21f2a_gate_acceptance.json
  u21f2a_gate_capsule.txt

The JSON proves Gate-recorded hash membership. The capsule proves accepted Gate
status and exact counters. Exact CLI candidate paths provide logical basenames,
and their computed hashes must already occur in the original JSON.

7. COMPOSITE EVIDENCE VALIDATION

7.1 Original Gate files

- both files must exist as regular non-symlink files;
- both must be inside the same directory whose basename is exactly
  `U21F2A_GATE_V01`;
- JSON must parse with UTF-8-sig support, duplicate-key rejection and finite
  JSON values only;
- capsule must match Section 2 exactly;
- record both evidence-file SHA-256 values before any side effect.

7.2 Candidate logical identity

Require exact source basenames from Section 5. Compute both source SHA-256
values using streamed binary reads. Require:

- both are 64 lowercase hexadecimal characters;
- they are different from each other;
- each computed candidate hash occurs at least once as an exact complete string
  value somewhere in the recursively traversed original Gate JSON;
- a shorter substring, uppercase conversion, filename-derived value or manually
  entered value does not count as a match.

The recursive traversal may inspect dictionary values and array elements but
must never alter ordering or content. This binds previously unnamed Gate hash
evidence to actual candidates without fabricating new Gate evidence.

7.3 Gate matrix consistency

Require the original JSON to contain integer evidence for R=2, P=4, D=12,
I=4 and X=0, either in one counts mapping or in clearly named scalar fields.
Because the exact Gate JSON layout is available to the implementer, map its real
field paths explicitly in code. Do not accept unrelated integers found by a
global numeric search. If any count cannot be unambiguously mapped, fail closed.

GateStatus, ReturnCapsule and candidate basenames are intentionally not required
inside JSON v0.1. Their authority comes from Sections 7.1 and 7.2.


8. REQUIRED PROMOTION SEQUENCE

Before copying:

1. validate all CLI paths and exact basenames;
2. require source candidates to be regular non-symlink files;
3. require programs-dir to exist outside 04_TEMP;
4. require evidence-dir not to exist;
5. validate composite Gate evidence under Section 7;
6. record source and Gate-evidence hashes.

Installation:

7. refuse to overwrite a non-identical destination;
8. copy source bytes through a private temporary file in programs-dir;
9. flush, fsync, hash-verify and atomically install the runtime name;
10. if an identical destination already exists, treat it as idempotent but
    still complete all checks;
11. prove both source/destination pairs byte-identical;
12. set installed runtime files read-only where supported.

Relocated validation:

13. launch the installed validator using sys.executable and installed names:

      <validator.py> --self-test --protocol-bundle <bundle.json>

14. require return code 0, no Traceback and exact final line:

      U21F2A1 N-T24-P4-D16-K4-X0 C-0

15. recompute source, destination and both Gate-evidence hashes;
16. require all originals unchanged and destinations still byte-identical;
17. write promotion evidence atomically.

Never import the validator and never rewrite any source/evidence text.


9. PROMOTION EVIDENCE

On success write exactly below the new evidence-dir:

10. TOOL SELF-TEST

Use private temporary synthetic files. Prove exactly 16 checks:

- P5 valid composite evidence, hash-membership binding, two-file byte install,
  relocated launch and idempotent install;
- D8 wrong capsule, duplicate JSON key, missing/unambiguous count failure,
  missing candidate-hash membership, wrong basename, hash mismatch,
  non-identical destination and relocated-self-test failure;
- I3 Gate evidence immutability, source immutability and exact runtime mapping;
- X0 uncontrolled failures.

Success:

  U21F2AP2ST N-T16-P5-D8-I3-X0 C-0

Failure:

  U21F2AP2ST N-T<t>-P<p>-D<d>-I<i>-X<x> C-7 K-<STABLE_REASON>


11. PROMOTION CAPSULE

Success:

  U21F2AP2 N-G2-H2-C2-R1-I4-X0 C-0

Meanings:

  G2  original Gate JSON and capsule validated as a composite set;
  H2  both computed candidate hashes occur in original Gate JSON;
  C2  both runtime destinations are byte-identical installations;
  R1  relocated complete validator self-test passed;
  I4  Gate files and both candidate sources remained unchanged;
  X0  no uncontrolled failure.

Failure:

  U21F2AP2 N-G<g>-H<h>-C<c>-R<r>-I<i>-X<x> C-7 K-<STABLE_REASON>
