UDP002 U22B15 执行指南
======================

这一步做什么
------------
B15读取已经通过的B14 v0.2全视频结果，回答：Radar无效率是否随着Camera目标绝对方位角增大而呈现一致的上升方向。

它使用全部50,026个方位角有效帧作为分母，不只看16个Candidate；同时用Camera距离分箱做一次粗粒度标准化，防止距离分布被误认为角度影响。

注意：`<2°`、`2–5°`、`>=5°`只是预先固定的统计比较组，不是雷达视野阈值。B15不会输出Root Cause或故障判定。

文件位置
--------
把ZIP中的两个文件解压到：

C-CODE\U-UDP002\04_TEMP

- u002_u22b15_bearing_association_assessment_v0_1.py.txt
- u002_u22b15_bearing_association_assessment_algorithm_card_v0_1.json

从C-CODE目录打开CMD。

CMD执行——三行
---------------
python U-UDP002\04_TEMP\u002_u22b15_bearing_association_assessment_v0_1.py.txt --prepare

python U-UDP002\04_TEMP\u002_u22b15_bearing_association_assessment_v0_1.py.txt --self-test

python U-UDP002\04_TEMP\u002_u22b15_bearing_association_assessment_v0_1.py.txt --execute

成功标准
--------
Self-test输出：

U22B15-SELFTEST-PASS-24-C0

正式执行输出一条B15 capsule，结尾为：

X0-C0

只需完整回传这一条B15 capsule，不用手抄CSV。

Capsule解释
-----------
- N：方位角有效总帧数
- I：其中Radar无效帧数
- B1至B8：每个方位角Bin的Exposure和Radar Invalid计数
- AC/AP：距离标准化后的中心组/外侧组失效率，每万帧表示
- S：中心组和外侧组都有曝光的距离分层数量
- TP/TN/TZ：分箱失效率Spearman方向为正/负/不可算，后接绝对值乘1000
- A1：三个方向检查一致为正
- A0：一致未观察到正方向
- A2：信息不足
- A3：方向混合

输出位置
--------
C-CODE\U-UDP002\07_OUTPUT\U22B15_BEARING_ASSOCIATION_ASSESSMENT_V01

主要文件：

- b15_bearing_bin_assessment.csv
- b15_bearing_group_comparison.csv
- b15_distance_standardization_details.csv
- b15_association_summary.json
- B15_RETURN_CAPSULE.txt

解释边界
--------
即使A1，也只能说“在这次数据中观察到一致的正向关联方向”。不能说5度是Radar极限，也不能说角度导致Radar丢失。下一步仍需结合时间连续性、转弯状态及人工视频证据决定是否进入阈值或动态Lag建模。
