1. OBJECTIVE

Build the first governed execution layer that turns one accepted U21E
RUN_PREFLIGHT_READY document into one controlled U002 Run.

U21F must:

- initialize one new U21A-compatible Run workspace;
- execute only the exact qualified Modules and bindings approved by U21E;
- isolate every Module invocation in a child process;
- validate every Module request, result, payload and Artifact Manifest;
- update S0-S7, Module, Artifact and Run states atomically;
- apply declared FailurePolicy without hidden continuation;
- preserve bounded diagnostics and input immutability evidence;
- produce a contract-valid governed Run or a contract-valid controlled failure.

U21F is execution infrastructure. It must not contain Camera/Radar algorithms,
statistics, SysID, baseline, residual, Candidate or U003 business logic.


2. POSITION AND OWNERSHIP

U21A  creates the governed Run identity, workspace and initial PENDING lifecycle.
U21B  establishes statically eligible Module identities.
U21C  proves selected Module software can pass its declared self-test.
U21D  creates a deterministic SOFTWARE_PLAN_READY order and Artifact graph.
U21E  binds that plan to exact U001 signals, configurations and Run scope.
U21F  executes the approved plan and commits verified Artifacts.
U21G  independently proves the complete synthetic vertical chain.

U21F must use the frozen outputs of U21A-U21E. It must not rewrite or extend
their source files, schemas or accepted evidence.

6. RUNTIME MODULE ABI v0.1

The Module Manifest already declares Entrypoint.RelativeFile and
Entrypoint.Callable. U21F freezes the callable convention:

  result = declared_callable(request)

Requirements:

- exactly one positional argument;
- request is a Python mapping loaded from a validated runtime request;
- return value is one JSON-serializable mapping;
- no DataFrame, numpy object, custom class or generator may cross the boundary;
- Module writes payload files only below its assigned staging output root;
- Module never writes an Artifact Manifest or Run Manifest;
- Module never edits U001, preflight, plan, Module Manifest or prior Artifact;
- Module does not decide its own Stage, identity, configuration or scope.

This ABI is a software interface, not an algorithm definition. U22 Algorithm
Cards and Module specifications will define each real Module's mathematics.


7. RUNTIME PROTOCOL BUNDLE

The JSON bundle must be a deterministic JSON Schema 2020-12 document containing
two definitions and exact constants:

  U002_MODULE_EXECUTION_REQUEST / version 0.1
  U002_MODULE_EXECUTION_RESULT  / version 0.1

Reject unknown top-level fields in both documents.

7.1 Request required logical fields

  ContractType
  ContractVersion
  RunId
  CaseId
  Stage
  ModuleIdentity
  Scope
  ClockDomain
  BoundSignals
  InputArtifacts
  Configuration
  ExecutionPolicy
  RuntimePaths

ModuleIdentity contains exact ModuleId, ModuleVersion, ManifestSha256,
ImplementationSha256 and Callable.

BoundSignals preserves U21E port identity, role, required/optional status,
selection mode, CanonicalNames, D3 semantic projection and exact D2 column
mapping. Do not let the executor search for replacement signals.

InputArtifacts contains exact upstream ArtifactId, type, schema identity,
ManifestSha256 and validated payload locations.

ExecutionPolicy contains TimeoutSeconds and MaxRetainedLogBytes.

RuntimePaths is explicitly ephemeral and may contain absolute company-local
paths required by the child process. It must never be copied into formal Run,
Artifact, export or diagnostic manifests. Formal evidence stores only logical
identities, relative paths and SHA-256 values.

7.2 Result required fields

  ContractType
  ContractVersion
  RunId
  Stage
  ModuleId
  ModuleVersion
  Status
  Artifacts
  Warnings
  Metrics

Status is SUCCEEDED, SKIPPED or FAILED.

Each Artifact declaration contains:

  ArtifactType
  ArtifactSchemaId
  ArtifactSchemaVersion
  Payloads
  CoordinateFrame
  UncertaintyReference
  Metadata

Each Payload declaration contains:

  RelativePath
  Role
  MediaType
  RowCount
  PayloadKind

The Module must not claim payload SHA-256 or ByteSize. The parent executor owns
those measurements from exact persisted bytes.

Metrics is limited to JSON scalar or short scalar arrays. It must not contain
raw CAN rows, complete signal series, absolute paths or binary/text payloads.


8. PROTOCOL VALIDATOR

The dedicated validator must support:

  --self-test --protocol-bundle PATH

  --validate-result FILE --protocol-bundle PATH

It must implement only the subset of JSON Schema used by the generated bundle,
reject unsupported keywords, reject bool-as-integer confusion, reject NaN and
Infinity, reject unknown fields, and print stable C-0/C-7 capsules.

The protocol bundle and validator are U21F candidates until independent Gate and
promotion complete. Do not modify the frozen U2-0A core schema or validator.

11. RUN INITIALIZATION

Use the promoted U21A Engine only through its CLI. Do not import private Engine
functions and do not modify the Engine source.

Required sequence:

1. record the exact set of RunId directories already under run-root;
2. invoke Engine `--init-run` with preflight CaseId, U001 identity, resolved
   scope, FRAMECOUNT clock and the supplied frozen core files;
3. require exit code 0 and bounded stdout/stderr;
4. compute the directory set difference and require exactly one new RunId;
5. validate its PENDING Run Manifest with the frozen validator;
6. preserve RunId, CreatedAtUtc and governed directory layout;
7. persist exact preflight, plan, Module Registry and resolved configuration
   snapshots under 00_CONFIG with exact hashes;
8. replace the skeleton Registry/config projections with the actual selected
   Module/configuration projections while retaining the explicit Engine Skeleton
   system Module identity;
9. update the Run Manifest atomically and revalidate it before execution.

Set-difference discovery is allowed. Modification-time discovery is prohibited.


12. ATOMIC MODULE TRANSACTION

For each selected Module in exact plan order:

1. recheck Manifest and implementation hashes;
2. verify required upstream Artifacts are COMPLETE and exact-hash valid;
3. create a unique private staging directory below the governed Stage;
4. construct and validate one runtime request;
5. launch this executor's worker mode as a child process using the same Python;
6. redirect stdout and stderr to files, never capture unbounded logs in memory;
7. enforce timeout; terminate, then kill if termination does not complete;
8. require controlled worker exit and a complete atomic result JSON;
9. validate the result through the protocol validator;
10. require identity, Stage and RunId to equal the request;
11. require declared Artifacts to match the Module Manifest ProvidesArtifacts;
12. reject missing, extra or colliding exclusive outputs;
13. reject absolute payload paths, parent traversal, symlinks and files outside
    the assigned staging root;
14. compute exact payload SHA-256, ByteSize and optional RowCount consistency;
15. require at least one PRIMARY payload for each successful Artifact;
16. construct Artifact Manifest(s) in the parent executor;
17. validate each through the frozen core validator;
18. atomically move the complete Artifact directory into 03_ARTIFACTS/Sx;
19. update Run Manifest Artifact index, Module status and Stage state atomically;
20. only then delete the private runtime request containing absolute paths.

No partial Artifact may be registered. Failed staging content may be moved into
02_DIAGNOSTICS/failed_modules after absolute paths and oversized logs are
redacted/truncated; it never becomes an accepted Artifact.


13. CHILD WORKER

The worker must:

- validate request before importing Module code;
- verify module file exact SHA-256 against request;
- import from the exact file path with a unique non-user-controlled import name;
- find exactly the declared callable and verify it is callable;
- call it once with one request mapping;
- require one mapping result and JSON serialization with allow_nan=false;
- atomically write result;
- catch exceptions only at the outer boundary and emit bounded diagnostic type,
  source basename, function and line without raw input values;
- never claim execution success if result validation fails.

U21F is process isolation, not an OS security sandbox. Approved Module identity,
read-only inputs, pre/post hashes and post-run validation remain required.


14. RUN AND STAGE STATE RULES

- Run begins PENDING, then RUNNING.
- Stages are processed S0 through S7 only.
- A Stage with no selected Module is an explicit successful no-op, not omitted.
- Stage InputArtifactIds and OutputArtifactIds contain actual validated IDs.
- A Module becomes SUCCEEDED only after all its Artifacts are committed.
- Later Stage cannot start while an earlier required dependency is unresolved.
- Existing Run or Artifact outputs are never overwritten.
- run_status.json, Run Manifest and event log remain consistent.
- Every governed JSON update is atomic and followed by validation.

Successful completion requires:

- every REQUIRED Module SUCCEEDED;
- every S0-S7 Stage reached a terminal governed state;
- at least one validated Artifact exists;
- all registered Manifest and payload hashes reconcile;
- U001 D2-D5 hashes still equal preflight;
- no uncommitted staging directory is presented as formal output.


15. FAILURE POLICY

ABORT_RUN:

- mark Module and current Stage FAILED;
- leave later Stages PENDING;
- mark Run FAILED and persist diagnostics;
- stop immediately.

BLOCK_DEPENDENT_PATH:

- mark failed Module FAILED;
- transitively mark only Artifact-dependent Modules SKIPPED;
- allow independent Modules to continue in fixed order;
- final Run is FAILED if the failed Module was REQUIRED, otherwise PARTIAL.

SKIP_OPTIONAL_PATH:

- valid only for OPTIONAL Module failure;
- mark failed optional Module SKIPPED with a diagnostic reason;
- skip only dependent optional path and continue independent work;
- final Run is PARTIAL unless no requested output was lost under the accepted
  plan; do not silently upgrade an incomplete requested path to SUCCEEDED.

Unexpected executor, protocol, identity, core-contract or input-mutation failure
always aborts the Run with C-7.


16. INPUT IMMUTABILITY

- Verify U001 D2-D5 hashes immediately before Run creation.
- Verify them again after the last child exits and before final success.
- Verify plan, preflight, Module Manifest, implementation and configuration
  identities before every applicable execution.
- Never write to U001 package or modules-root.
- Record only hashes and logical identities in formal evidence.

The executor does not need to hold full D2 in memory. SHA-256 must stream fixed
binary chunks. This protects correctness without reintroducing U001's memory
growth problem.


17. LOG AND RESOURCE BOUNDARY

- Parent control plane is standard-library and streaming.
- No full U001 CSV is loaded by U21F.
- Child stdout/stderr go to files, with only the configured retained tail/head.
- Record original byte count when truncating retained logs.
- Default timeout for synthetic self-test: 30 seconds per Module.
- Default production timeout when not specified: 600 seconds per Module.
- Default retained log size: 262144 bytes per stream.
- Timeout and limits are persisted in resolved configuration evidence.
- v0.1 has no multiprocessing, resume, cache reuse, GUI or EXE packaging.
