U001 H6B5D3 FrameCount路径诊断 - 执行说明
============================================

目的
----
一次查清以下三个问题：

1. 原始CANDump.csv中实际有多少条完整的CH2 0x620消息；
2. H2是否遗漏了FrameCount解码；
3. 四个已选CAN消息组是否分布在不同的SourceRow区段，导致H3不能按源行进行跨组同步。

本程序只读原始CSV和H2/H3证据，不排序、不填补、不修改任何数据。
全量扫描原始CSV期间，每读取50000行会显示一次进度。

放置位置
--------
将两个文件直接放入：
C-CODE\U-UDP001\04_TEMP

从C-CODE目录依次执行（仅三行）
--------------------------------
python U-UDP001\04_TEMP\u001_h6b5d3_frame_key_path_diagnostic_v1_0.py.txt --prepare
python U-UDP001\04_TEMP\u001_h6b5d3_frame_key_path_diagnostic_v1_0.py.txt --self-test
python U-UDP001\04_TEMP\u001_h6b5d3_frame_key_path_diagnostic_v1_0.py.txt --execute

需要回传
--------
只回传execute最后三行：

H6B5D3-...
H6B5D4-...
H6B5D5-...

判断方式
--------
- D3中的P1：原始完整0x620行数与H2 FrameCount更新数一致，Decoder没有漏掉0x620。
- D3中的P0：两者不一致，需要修复H2 Decoder。
- D4：检查DateTime/Time[us]在原始源行中是否倒退。
- D5：列出每个已选CAN消息组的更新数、首末源行及位于最后FrameCount之后的行数。

在三行结果返回前，不修改MaxAssignmentAgeRows，也不进入H4。
